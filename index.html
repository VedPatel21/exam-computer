Conventions used throughout

Arrays are zero-indexed: an array of length n has indices 0 through n−1. Ranges lo..hi include both endpoints unless explicitly described as half-open. Concept & explanation

1.1 Values, variables, and types

Concept · definition

A value is a piece of information: the integer 7, the character 'A', or the Boolean value true. A variable is a name used to refer to stored information. Think of a labelled box whose contents can change. The label and the contents are different: score is a name; 7 might be its current value.

An integer is a whole number such as −3, 0, or 12. A Boolean has two possible values, true and false. A type specifies what kind of value is expected and which operations are meaningful. Adding integers makes sense; following a pointer means accessing an object through its address. Confusing those operations produces incorrect programs.

Source example · notation / trace
score ← 7
bonus ← 3
score ← score + bonus

The first line stores 7 in score. The second stores 3 in bonus. On the third line, evaluate the right-hand side using the old values: 7+3=10. Then replace score with 10. bonus stays 3. Assignment is an action, not a mathematical assertion that a number equals itself plus something.

A trace records the values after instructions execute. Tracing is a reliable way to understand unfamiliar code: change only what the current instruction changes.

An if statement chooses instructions according to a condition:

Algorithm · pseudocode
if score ≥ 10:
    message ← "pass"
else:
    message ← "try again"

Only one branch executes. Indentation shows which instructions belong to a branch or loop. A branch is not repeated just because its condition stays true; repetition requires a loop or another function call.

Concept & explanation

1.3 Arrays and indices

An array stores a fixed number of slots in consecutive memory locations. Its length is its number of slots. An index selects a slot, not the value in that slot.

Source example · notation / trace
index       0     1     2     3
A         [ 6 |   2 |   9 |   4 ]

Here A[2] is 9, and A[0] is 6. A[4] is outside this four-element array. Reading beyond the valid range is an error, not a request for a default value. A[1] ← 8 replaces the 2 with 8; it does not insert a new slot.

An array of n items ends at index n−1 because counting starts at zero. A source using one-based indexing ends at n instead. Always write the convention before tracing an algorithm. For example, the fourth element has zero-based index 3 and one-based index 4.

Concept & explanation

1.4 Integer division, remainder, and swapping

For nonnegative integers, a div b is the whole-number quotient, and a mod b is the remainder, with b>0. Thus 17 div 5=3 and 17 mod 5=2 because 17=3×5+2. floor(x) is the greatest integer no greater than x: floor(3.8)=3 and floor(−1.2)=−2. We use floor division on nonnegative sizes and indices. C++ integer division truncates toward zero; that differs from floor for some negative inputs.

Remainder makes an index wrap around: (4+1) mod 5=0. It also tests parity: n is even when n mod 2=0. To exchange two values, preserve one before overwriting it:

Source example · notation / trace
temp ← x
x ← y
y ← temp

Starting x=4, y=9 gives temp=4, then x=9, then y=4. Writing x ← y; y ← x instead makes both values 9 because the original 4 was lost.

Concept & explanation

1.5 Repetition

A for loop is useful when the positions to visit are known:

Algorithm · pseudocode
total ← 0
for i ← 0 to n−1:
    total ← total + A[i]

For A=[6,2,9], the loop visits i=0,1,2. The running totals are 6,8,17. There are n additions. The loop variable changes automatically according to the stated range.

A while loop repeats while its condition is true:

Algorithm · pseudocode
j ← 1
while j < 10:
    j ← 2*j

The values after updates are 2,4,8,16. The body executes four times. The condition is checked a fifth time, sees 16<10 is false, and stops. Count body executions separately from condition checks. A loop needs progress toward termination; while j < 10: j ← j never terminates when it starts with j=1.

Concept & explanation

1.6 Functions, parameters, and return values

A function packages instructions under a name. Its parameters are names for its inputs. A call supplies actual input values, called arguments. return sends an answer to the caller and ends that call.

Algorithm · pseudocode
Larger(x, y):
    if x > y:
        return x
    return y

answer ← Larger(3, 8)

In this call x=3 and y=8. The condition is false, so the call returns 8 and answer receives 8. Local variables belong to that call. A function can also modify a shared array or node; returning a number and modifying an object are different actions. Print(A) may display values without returning an array. Reverse(head) may change links and return a new head pointer.

Concept & explanation

1.7 Memory, addresses, pointers, and references

Concept · definition

Memory stores values in addressable locations. An address identifies a location. A pointer stores an address, allowing a program to find an object. The address is not the object's data value.

Text diagram · source example
variable p contains address 1200
             |
             v
address 1200: [ value: 7 | next: NIL ]

The node's value is 7; its address is 1200; p stores 1200. p.value means follow p to the node, then read the value field. In C++ a pointer would commonly use p->value. A C++ reference is an alias for an existing object, whereas a pointer is a variable that can store an address or be null. In diagrams, “reference” is sometimes used broadly for an object link; this book states pointer operations explicitly.

NIL means there is no object to follow. Reading p.value when p=NIL is invalid. Assigning q ← p copies the address, not the node. Both names then reach the same node. If q.value ← 10, reading p.value also gives 10. To create an independent node, allocate a new node and copy its fields. Chapter 7 develops this distinction through complete list operations.

Worked example

1.8 Worked example: finding a maximum

For a nonempty array, keep the largest value seen so far:

Algorithm · pseudocode
Maximum(A, n):
    require n ≥ 1
    best ← A[0]
    for i ← 1 to n−1:
        if A[i] > best:
            best ← A[i]
    return best

On [6,2,9,4], best starts at 6, remains 6 after inspecting 2, becomes 9 after inspecting 9, and stays 9 after inspecting 4. At every step it is the largest inspected value. Once all items have been inspected, it is the maximum of the whole array. That statement is a first example of an invariant, something maintained throughout a process.

There are n−1 value comparisons. Initializing, accessing each array item, comparing, and sometimes updating all take bounded work per item under our model. Total work grows linearly with n, written Θ(n), which Chapter 4 defines precisely. Even if the first item is largest, this algorithm still inspects all remaining items.

Initializing best to 0 is unsafe: on [−7,−2,−9] it would return 0, which is not an input element. Initializing from an actual item handles negative inputs without a special guess. An empty array requires a separate contract, such as reporting that no maximum exists.

Important takeaway

1.10 Mistakes, recap, and reference candidates

Do not confuse a variable's name with its value, an index with an element, assignment with equality, or an address with the value stored at that address. Do not read a nonexistent array slot or follow NIL. Trace updates in order: an assignment takes effect immediately.

You can now read a small function, follow choices and loops, and record changes. Reference candidates: valid indices 0..n−1; quotient/remainder identity; swap using a temporary; maximum scan with n−1 comparisons; declare assumptions before analyzing code.

Concept & explanation

2.1 Organization changes what is easy

Imagine keeping books in a numbered row or in boxes linked by directions to the next box. The row makes “give me position 20” straightforward. The links make “place this box immediately after the box I already hold” straightforward. Neither arrangement wins every task. A data structure is chosen for the operations a program needs, not because its name sounds advanced.

Concept · definition

A data structure stores information together with rules for accessing and changing it. An algorithm is a procedure that uses information to solve a problem. A linked list is a structure; walking through it to find the largest value is an algorithm. The same maximum algorithmic idea, inspecting every value, can be implemented using arrays or links.

An abstract data type describes what operations mean without prescribing memory layout. A stack says that removing returns the most recently added remaining item. It can be implemented with an array or linked nodes. The behavior is the interface; the storage and code are the implementation.

Concept & explanation

2.2 Sets, sequences, and duplicates

A mathematical set records membership without order or repeated copies: {2,5,9} is the same set as {9,2,5}. A sequence records order and may contain duplicates: [2,5,2] differs from [5,2,2]. Its length is 3 even though it contains only two distinct values.

This changes the meaning of insertion and deletion. Insert 5 into a set that already contains 5 and membership need not change. Insert 5 at position 1 in a sequence and both its length and positions change. Deleting “the item at index 1” differs from deleting “some item with value 5.” A complete problem statement identifies which operation is intended.

Concept & explanation

2.3 Contracts and representations

An operation's contract states the inputs it accepts and the result it promises. Insert(i,x) in a length-n sequence usually allows 0≤i≤n: i=n means append. Access(i) requires 0≤i<n. A contract can also state that a function changes the structure or leaves it unchanged.

A representation invariant is a condition that stored fields must satisfy whenever an operation finishes. For an array-backed sequence with capacity C and size n, a useful invariant is 0≤n≤C and the live items occupy slots 0..n−1. Slots n..C−1 are spare capacity, not extra sequence elements. For a singly linked list, following next pointers from head should visit exactly the nodes in sequence order and eventually reach NIL.

Correctness has two layers: the operation must produce the required abstract behavior and preserve the representation invariant. A queue that returns the right item once but leaves the head field pointing into invalid memory is not a correct implementation.

Concept & explanation

2.4 Same operation, different cost

An array calculates the address of A[i] from the base address, index, and fixed slot width. It does not visit positions 0 through i−1. This is why array access is constant-time in the standard model.

A singly linked list's head points only to the first node. To reach the third, follow two next links. Reaching a position near the end requires walking through many nodes. But inserting after an already known node can change two links, without moving the later nodes.

Text diagram · source example
Array:  [8 | 3 | 6]          access index 2 directly

List:   head -> [8] -> [3] -> [6] -> NIL
                       traverse links to reach 6

“Linked-list insertion is constant-time” needs an assumption: the location or predecessor is already known and allocation is constant-time. Finding that location by index may take linear time. “Array insertion is linear” also needs context: inserting at the end with spare capacity does not shift a suffix. Chapters 6 and 7 give the full operation tables.

Worked example

2.5 Worked example: choose a structure

Suppose a program repeatedly requests the item at a random index, occasionally appends, and almost never inserts in the middle. A dynamic array is a reasonable choice: indexed reads are constant-time, and appends have constant amortized cost. If the program instead repeatedly inserts after a node it already holds, a linked list can avoid shifting. There is no need to claim the list makes random access fast; the workload does not require it.

An exam-quality answer links each required operation to its cost and states the assumptions. “Use a list because it is flexible” is too vague. “Use a singly linked list because insertion after the known predecessor changes only a constant number of links” is a technical justification.

Concept & explanation

2.6 A sequence algorithm: majority detection

A majority element occurs more than n/2 times. In [4,2,4,4,3], 4 occurs 3 times and 3>5/2. In [4,2,4,2], neither value occurs more than half. Merely being the most frequent is not enough.

A simple method counts occurrences separately for every candidate: n candidates, each with a full n-element scan, giving Θ(n²) work. A more efficient method cancels pairs of different values. Such a cancellation cannot eliminate a genuine majority: at most one majority copy is removed with each non-majority copy, and the majority initially has more copies.

Algorithm · pseudocode
Majority(A, n):
    balance ← 0
    for each x in A:
        if balance == 0:
            candidate ← x
            balance ← 1
        else if x == candidate:
            balance ← balance + 1
        else:
            balance ← balance − 1
    if n == 0:
        return NONE
    count ← number of items equal to candidate
    if count > n/2:
        return candidate
    return NONE

On [4,2,4,4,3], (candidate,balance) becomes (4,1),(4,0),(4,1),(4,2),(4,1). The candidate is 4; a second pass verifies its count. That verification is essential when no majority is guaranteed. On [1,2,3], a candidate can survive despite no majority. Two full passes each take Θ(n), so their sum is Θ(n), not Θ(n²). Only a few variables are stored, giving Θ(1) auxiliary space. This is an added standard teaching algorithm for the majority problem mentioned in [L]; the exact classroom implementation was not provided.

2.7 Independent practice

Try it yourself · 2.1

2.1 Explain why [2,7,2] and [7,2,2] represent the same set of values but different sequences.

Show answer

2.1. Both sequences have membership set {2,7}. A set ignores order and multiplicity. The sequences have different first and second positions, so they are different sequences despite equal membership and multiplicities. A sequence answer must preserve the order required by its contract.

Try it yourself · 2.2

2.2 For a size-3 sequence, list every legal insertion index and every legal access index.

Show answer

2.2. For size 3, access indices are 0,1,2. Insertion indices are 0,1,2,3. Index 3 is a valid insertion after all existing items but is not yet an accessible live item. After insertion the size becomes 4, making index 3 accessible.

Try it yourself · 2.3

2.3 Trace the majority candidate/balance on [5,5,2,3,5,5] and explain whether verification can be omitted. Answers: Appendix A, Chapter 2.

Show answer

2.3. Candidate/balance pairs after [5,5,2,3,5,5] are (5,1),(5,2),(5,1),(5,0),(5,1),(5,2). Verification counts four copies of 5, and 4>6/2, so 5 is a majority. Unless existence was guaranteed by the problem, verification cannot be omitted: cancellation always leaves some candidate on many no-majority inputs, such as [1,2,3]. The candidate's existence alone proves nothing about its frequency.

Important takeaway

2.8 Mistakes, recap, and reference candidates

State the operation before its complexity. Separate finding a position from updating that position. Separate spare storage from live data. A majority is strictly more than half, not at least half. An interface specifies behavior; a representation explains how that behavior is implemented. Reference candidates: operation contracts; size≤capacity; array/list access tradeoff; majority cancellation plus verification.

Concept & explanation

3.1 Powers and roots

The exponent in 2³ tells us to multiply three copies of 2: 2³=8. For a positive integer k, nk multiplies k copies of n. Exponent rules come from counting those copies: xa xb=xa+b, (xa)b=xab, and xa/xb=xa−b for nonzero x. Also x⁰=1 for x≠0.

An exponent can contain n. Then 2n doubles whenever n increases by one. This is very different from n², which squares n. At n=10, n²=100 and 2n=1024; at n=20 they are 400 and 1,048,576. A polynomial has fixed nonnegative integer powers of n combined with constant coefficients. An exponential such as 2n has a fixed base greater than 1 and a growing exponent.

The square root √n is the nonnegative number whose square is n. Thus √25=5 and √n=n1/2. Fractional powers matter when comparing growth rates: n1/2 grows more slowly than n, while n3/2 grows faster than n but slower than n².

Concept & explanation

3.2 Logarithms answer a reverse question

log₂ n asks: “To what power must 2 be raised to obtain n?” Because 2³=8, log₂8=3. Because 2¹⁰=1024, log₂1024=10. A logarithm need not be an integer: log₂10 lies between 3 and 4.

This explains halving loops. Starting with 16, repeatedly halving gives 16,8,4,2,1: four halvings. Starting with 1024 needs ten. The number of times n can be halved before reaching 1 is about log₂ n. Doubling from 1 to n asks the same question in reverse.

n 1 2 4 8 16 32 1024
log₂ n 0 1 2 3 4 5 10

For b>1 and positive x,y, logs turn multiplication into addition and powers into multiplication:

logb(xy)=logbx+logby,logb(xk)=klogbx.log_b(xy)=log_b x+log_b y,; log_b(xk)=klog_b x.

Thus log(n²)=2 log n, not (log n)². Also log(x/y)=log x−log y, and change of base gives log_b n=(log₂ n)/(log₂ b). If b is fixed, the denominator is a constant. This is why fixed logarithm bases do not affect Θ(log n).

There is no general identity log(x+y)=log x+log y. At x=y=2, log₂4=2 while log₂2+log₂2=2 happens to agree; at x=y=4, log₂8=3 while log₂4+log₂4=4. A few numerical coincidences do not prove a rule.

Nested notation needs careful reading. log log n means log(log n), not (log n)². For large n, log log(nn)=log(n log n)=log n+log log n. This identity explains one of [A1]'s growth comparisons. We consider sufficiently large n so each logarithm is defined.

Concept & explanation

3.3 Floors, ceilings, and exact loop counts

ceil(x) is the least integer no smaller than x. If j starts at 1 and doubles while j<n, after t updates j=2^t. The first t with 2^t≥n is ceil(log₂ n), for integer n≥1. With j≤n, the exact count changes: when n=8 the loop visits j=1,2,4,8, giving four executions, not three. These differences usually preserve the growth class but matter in traces.

Concept & explanation

3.4 Sigma notation is a compact loop

The expression below says “add i as i runs from 1 to n”:

Σi=1ni=1+2+…+n=n(n+1)2.sum_(i=1)ni=1+2+…+n=(n(n+1))/(2).

At n=4 it means 1+2+3+4=10. Pairing the first and last terms gives 1+n, 2+(n−1), and so on. There are n terms, each averaging (n+1)/2, so the total is n(n+1)/2. This also works when n is odd: the middle term equals that average.

The letter i is a summation index. Changing it to j does not change the sum. The bounds do matter. A sum from i=0 to n contains n+1 terms. A constant summed n times gives Σ (i=1..n) c=cn. Constants factor out: Σ c f(i)=c Σ f(i). Sums distribute over addition, but a product of sums is not generally the sum of products.

Useful checked identities are:

Σi=1ni2=n(n+1)(2n+1)6,Σi=1n1=n.sum_(i=1)ni2=(n(n+1)(2n+1))/(6),; sum_(i=1)n1=n.

For runtime work, the first is Θ(n³) and the second Θ(n). The exact formula is useful when asked for a count; its dominant growth is useful when asked for a complexity class.

Concept & explanation

3.5 Geometric series

In a geometric series, successive terms differ by a fixed multiplicative factor. For example 1+2+4+8=15. Multiplying the sum by 2 shifts every term: 2+4+8+16. Subtract the first sum from the second; all internal terms cancel, leaving 16−1.

1+2+…+2k=2k+1-1.1+2+…+2k=2k+1-1.

More generally, Σ (i=0..k) ri=(rk+1−1)/(r−1) when r≠1. A doubling series is controlled by its last term within a constant factor. A halving series n+n/2+n/4+… is less than 2n. These facts explain both dynamic-array copying and recursion-tree costs.

Concept & explanation

3.6 Bounding a sum when no exact formula is needed

Consider S(n)=Σ (i=1..n) log i. Each term is at most log n, so S(n)≤n log n. For a lower bound, use only the last half of the terms. There are about n/2 terms with i≥n/2, and each is at least log(n/2). Therefore S(n)≥(roughly n/2)log(n/2), which grows as n log n. Together the bounds establish Θ(n log n).

The purpose of the lower bound is to show that the upper estimate is not much too large. Bounding every term by log n proves only an upper bound. Keeping a substantial block of large terms proves a matching lower bound. Floors and ceilings alter constants, not this classification.

Concept & explanation

3.7 Factorials and comparing unusual functions

n! means 1×2×…×n. For n distinct items, there are n! possible input orders: n choices for the first item, n−1 for the second, and so on. Comparison-sorting lower bounds use this count. You do not need Stirling's formula to show log(n!)=Θ(n log n): it equals Σ log i, whose bounds were just proved.

To compare positive functions, a useful tool is their ratio. If f(n)/g(n) tends to 0, f grows strictly more slowly; if it tends to a positive finite constant, they have the same Θ class. Taking logs can simplify huge positive expressions. For example log((log n)n/2)=(n/2)log log n, which eventually exceeds log(n³)=3 log n. Thus that log-to-a-growing-power expression eventually exceeds every fixed polynomial. It is not simply n log n.

For fixed k>0 and ε>0, (log n)k grows more slowly than nε. Intuitively, writing n=2t turns the comparison into tk versus 2εt; repeated multiplication by a constant greater than 1 eventually beats any fixed-degree polynomial in t. Chapter 4 uses this standard growth fact in grouping problems.

Runtime analysis

4.1 Count work before measuring seconds

A runtime measurement in seconds depends on hardware, language, compiler, and input. Counting fundamental operations isolates the relationship between input size and work. If a maximum scan compares each item after the first once, it makes n−1 value comparisons regardless of the processor's speed.

A cost model says which actions count as basic. We use constant-time arithmetic on machine-sized values, comparisons, pointer operations, and array reads/writes. An expression such as sum ← sum + j*i costs a constant number of such actions; its numeric result becoming large does not itself multiply the number of instructions under this model. If integers need an unbounded number of bits, arithmetic may no longer be constant-time. State the model when it affects a result.

Input size must be defined. For an array, n normally means its number of elements. For interleaving two length-n lists, there are 2n nodes, but Θ(2n)=Θ(n). For a number supplied in binary, its bit length is about log₂ of its numeric value; a runtime linear in the numeric value can be exponential in the bit length.

Runtime analysis

4.2 Upper bounds: Big-O

For eventually nonnegative functions f and g, f(n)=O(g(n)) means constants c>0 and n₀ exist such that f(n)≤c g(n) for every n≥n₀. Beyond a starting point, a constant multiple of g bounds f from above.

For f(n)=3n+2, choose c=5 and n₀=1. Since 3n+2≤5n when n≥1, f is O(n). It is also O(n²), because 5n≤5n² for n≥1. Big-O does not necessarily name the tightest bound. When a question requests a meaningful runtime, give the tightest justified class or explicitly state that you are giving only an upper bound.

Common mistake

The constant c must not depend on n. Trying c=n is not a valid way to prove that n² is O(n). It would change the promised constant as the input changes.

Runtime analysis

4.3 Lower bounds: Big-Omega

f(n)=Ω(g(n)) means constants c>0 and n₀ exist such that f(n)≥c g(n) for every n≥n₀. This is a lower bound on growth. For 3n+2, c=3 and n₀=1 prove Ω(n).

A lower bound can concern one algorithm or every algorithm in a problem model. “This scan takes Ω(n)” and “every comparison sort needs Ω(n log n) comparisons in the worst case” are different claims with different proofs. Neither is automatically a statement about best-case inputs.

Runtime analysis

4.4 Tight bounds: Big-Theta

f(n)=Θ(g(n)) means both O(g(n)) and Ω(g(n)). Equivalently there are positive constants c₁,c₂,n₀ with c₁g(n)≤f(n)≤c₂g(n) for every n≥n₀. Thus 3n+2=Θ(n).

For f(n)=4n²+7n+9 and n≥1, 4n²≤f(n)≤20n², so f=Θ(n²). Dropping lower-order terms is justified because constants can absorb them for sufficiently large n. It is not a claim that 4n²+7n+9 literally equals n².

Runtime analysis

4.5 Best, worst, average, and amortized are different axes

For a fixed input size n, best-case time is the smallest runtime over valid inputs of that size, and worst-case time is the largest. Average-case time requires a distribution over inputs or randomness. Expected time can average over an algorithm's random choices for a fixed input. Without specifying the relevant probability model, “average” is unsupported.

Linear search that stops when it finds a target takes Θ(1) in its best case (target first) and Θ(n) in its worst case (target last or absent). You can describe the worst-case function with O, Ω, or Θ; these symbols do not choose the input case for you. The sentence “Big-O is worst case and Omega is best case” is incorrect.

Amortized analysis bounds the total cost of a sequence of operations, divided across those operations. It uses no probability distribution. Dynamic-array append can have Θ(n) worst-case cost for one resize but Θ(1) amortized cost across many appends. Chapter 6 proves this and then explains [A1]'s stronger worst-case guarantee.

4.7 Properties used in analysis

Bounds are transitive: if f=O(g) and g=O(h), then f=O(h). If f=Θ(g), multiplying both by a positive constant preserves the class. For nonnegative costs, adding two algorithms' costs gives a class governed by the larger term: Θ(n)+Θ(n²)=Θ(n²). A loop that repeats a Θ(n) task n times takes Θ(n²), but sequential Θ(n) tasks do not multiply.

Common mistake

Be careful with subtraction. From f=Θ(n) and g=Θ(n), it does not follow that f−g=Θ(n). Taking f=g=n gives zero. Dominant-term simplification of a concrete expression is safe only after checking cancellation and eventual nonnegativity.

The notation f=o(g) means f/g tends to zero: strictly smaller growth. f=ω(g) means f/g tends to infinity. These appear in [A1]'s grouping instructions. f=O(g) permits a tie; f=o(g) does not. Also the equality sign in f=O(g) is conventional membership notation, not symmetric arithmetic equality.

Worked example

4.8 Worked examination-style explanation

Compare algorithms with T₁(n)=1000n and T₂(n)=n². At n=10 the costs are 10,000 and 100, so the quadratic one is faster under these formulas. At n=1,000,000 the linear one costs one billion operations and the quadratic one one trillion. Their crossover occurs at n=1000.

If only Θ(n) and Θ(n²) are given, these exact numerical choices cannot be established because hidden constants are unknown. The linear algorithm eventually wins for sufficiently large inputs, but growth classes alone do not decide every small or specified finite input. This is the nuance behind [S25]'s short-answer comparison.

Runtime analysis

5.1 A repeatable counting method

First identify the input size and the operation being counted. Next count how often each loop body executes. If an inner count depends on an outer variable, write that dependence before summing. Add sequential work; multiply only when a task is actually repeated. Finally establish a tight class if Θ is requested.

For for i ← 0 to n−1: total ← total+1, the body executes n times. A loop test and increment add a constant amount per iteration, plus one final test. Thus counting the body or all primitive operations gives the same Θ(n) class. Exact instruction counts depend on the chosen model, which should be stated if requested.

Runtime analysis

5.2 Independent nested loops

Algorithm · pseudocode
for i ← 0 to n−1:
    for j ← 0 to n−1:
        visit(i, j)

Assume visit is constant-time. For each of n i values, there are n j values, so there are n² calls. At n=3 the pairs are (0,0),(0,1),(0,2),(1,0),…,(2,2). The rectangular set of pairs is a useful visual model. If the inner loop ran m times instead, the count would be nm and the runtime Θ(nm), not Θ(n²) unless m is tied to n.

Two consecutive n-iteration loops have 2n body executions, so Θ(n). Their indentation tells you whether they are nested. The mere presence of two loops does not imply quadratic time.

Runtime analysis

5.3 Triangular and dependent loops

Algorithm · pseudocode
for i ← 1 to n:
    for j ← 1 to i:
        work()

The inner counts are 1,2,…,n. At n=4, draw rows of lengths 1,2,3,4; the total is 10. In general Σ i=n(n+1)/2=Θ(n²). Saying the inner loop is O(n) gives an O(n²) upper bound. To justify Θ directly, use the exact sum or note that the last n/2 rows each contain at least n/2 items, yielding Ω(n²).

If the inner loop starts at j=i and ends at n, its count is n−i+1. The total is again the same arithmetic series. Endpoint arithmetic matters: n−i gives zero when i=n, but an inclusive loop at that point actually executes once.

Runtime analysis

5.4 Doubling, halving, and mixed counts

Algorithm · pseudocode
j ← 1
while j < n:
    work()
    j ← 2*j

After t iterations j=2t, so the count is ceil(log₂ n) for n≥1. The runtime is Θ(log n) for growing n. Replacing doubling by multiplication by any fixed c>1 changes the logarithm's base, preserving the class. Adding 2 each iteration instead produces Θ(n) iterations; multiplicative progress is the key distinction.

Now consider an outer n-iteration loop with that doubling loop reset each time. Each outer iteration performs Θ(log n), so total Θ(n log n). If j is not reset, the analysis changes: a single shared j can double only about log n times in total. Never assume a reset that the code does not contain.

For j ← n; while j>0: j ← floor(j/2), the body executes floor(log₂ n)+1 times for positive integer n. Floor division reaches zero. With real arithmetic and no rounding, repeatedly dividing a positive value by 2 never makes it exactly zero, so termination requires the correct model.

Runtime analysis

5.5 An inner loop whose size changes

Algorithm · pseudocode
for i ← 1 to n:
    j ← 1
    while j < i:
        j ← 2*j

For a fixed i, the number of updates is ceil(log₂ i), including zero updates at i=1. Total runtime includes loop overhead and is Θ(n+Σ log i)=Θ(n log n). The last-half lower-bound argument from Chapter 3 supplies the matching lower bound. It would be wrong to say Θ(log n) because the doubling process restarts for every i.

[A1]'s version lets i run to n². Substitute x=n² into the same summation bound: Θ(x log x)=Θ(n² log(n²))=Θ(n² log n). The factor 2 from log(n²)=2 log n is constant.

for i ← 1 to n:

5.7 Changing the input variable inside a while loop

When code changes n itself, record the original size N before counting. A loop that repeatedly replaces n with n−1 takes Θ(N) steps, while one that repeatedly replaces it with floor(n/2) takes Θ(log N). Its final n=0 is not the input size to use in the answer.

Branching can still guarantee shrinkage over a bounded number of steps. If one branch doubles an odd n and the next branch divides the now-even result by 4, that two-step block reduces the value to about half its earlier size. Counting only the increasing line would give a false nontermination claim. Chapter 18 solves the exact [S25] loop and supplies both upper and lower bounds.

To show termination, find a quantity that decreases regularly toward a stopping value. It may decrease after a small block of operations rather than after every single line. To show Θ(log N), also check that one step cannot reduce a very large value by an arbitrarily huge factor; otherwise O(log N) might not be tight.

Worked example

5.8 Worked problem: a geometric amount of work

Algorithm · pseudocode
i ← 1
while i ≤ n:
    for j ← 1 to i:
        work()
    i ← 2*i

The outer loop has logarithmically many rounds, but the inner work is not n in every round. The counts are 1,2,4,…,2floor(log₂ n). Their sum is less than 2n. The last term is at least n/2, so the total is also Ω(n). Therefore runtime is Θ(n). Multiplying “log n rounds” by “at most n each” gives a valid but loose O(n log n) bound; the sum gives the tight answer.

Concept & explanation

6.2 Insertion shifts the suffix to the right

In simple words

To insert 9 at index 1, the old 3 and 6 need later positions. Move from the right end first, so a value is not overwritten before it is copied:

Algorithm · pseudocode
InsertAt(A, n, C, i, x):
    require 0 ≤ i ≤ n and n < C
    for j ← n downto i+1:
        A[j] ← A[j−1]
    A[i] ← x
    return n+1

On [8,3,6,.,.,.], copy A[2] to A[3], then A[1] to A[2], then put 9 in A[1]. Live result: [8,9,3,6]. Copying from left to right would propagate the overwritten 3 into later positions. There are n−i moves and one write, so time is Θ(n−i+1). Appending at i=n with spare capacity is Θ(1); inserting at the front is Θ(n).

Concept & explanation

6.3 Deletion shifts left

Algorithm · pseudocode
DeleteAt(A, n, i):
    require 0 ≤ i < n
    removed ← A[i]
    for j ← i to n−2:
        A[j] ← A[j+1]
    return (removed, n−1)

Deleting index 1 from [8,9,3,6] copies 3 left and then 6 left. The live sequence becomes [8,3,6]. The old last slot may still contain 6 physically, but the new size excludes it. Time is Θ(n−i), which includes Θ(1) for deleting the last item. If order is irrelevant, replacing a removed item by the last live item can avoid shifting, but that implements a different contract.

Concept & explanation

Maintaining sorted order still requires shifting for insertion/deletion, so those updates can be Θ(n). Fast search does not imply fast updates.

6.5 Dynamic growth and amortized cost

When storage is full, allocate a larger array, copy all n items, and then append. Growing by only one slot each time copies 1+2+…+(m−1)=Θ(m²) items across m appends. Doubling capacity instead copies 1+2+4+…<2m items. Including m new-element writes, the total over m appends is Θ(m), so each append costs Θ(1) amortized.

This does not make every append constant-time. The append that copies n items still has Θ(n) worst-case cost. Amortized cost spreads a provable total across a sequence; it does not describe a random input or an average measured over lucky operations.

The capacity invariant also matters for space: ordinary doubling keeps capacity within a constant factor of live size after initialization. Reallocating on every small size change can be expensive. Shrinking with a gap between grow and shrink thresholds prevents repeatedly copying around a single boundary; detailed shrink policies are enrichment, not required by [A1]'s append-only problem.

Concept & explanation

6.6 Incremental copying: do a little before the emergency

[A1] asks for worst-case Θ(1) append and access, allowing constant-time allocation, no deletions, and appends only. Its idea is to prepare the next array while the current one still has room. Each append copies a fixed number of items, so no single append must copy the entire array.

Keep arr of even capacity C and a preparation array nextArr of capacity 2C. During a phase, size s lies between C/2 and C. All s live elements remain available in arr. nextArr holds a correctly copied prefix of length 2s−C after each completed append in that phase. When s=C, that prefix has length C: the entire live sequence has been prepared.

Algorithm · pseudocode
Append(x):
    if C == 0:
        arr ← allocate(2)
        nextArr ← allocate(4)
        arr[0] ← x
        C ← 2
        s ← 1
        return

    arr[s] ← x
    copied ← 2*s − C          // s is the OLD size here
    s ← s + 1
    nextArr[copied] ← arr[copied]
    nextArr[copied+1] ← arr[copied+1]
    if s == C:
        fresh ← allocate(4*C)
        release(arr)
        arr ← nextArr
        nextArr ← fresh
        C ← 2*C

Access(i):
    require 0 ≤ i < s
    return arr[i]

The old size satisfies C/2≤s≤C−1 before an ordinary append. Therefore copied=2s−C is nonnegative, and copied+1≤s. Both copied positions are valid after writing the new item at index s. This check prevents an out-of-bounds copy in a seemingly simple constant-time algorithm.

Worked example

6.7 Full phase trace and proof

Suppose C=4,s=2, arr begins [2,6,.,.], and nextArr has capacity 8 with an empty copied prefix. Append 8 writes arr[2], calculates copied=0, and copies indices 0 and 1. Now s=3 and nextArr begins [2,6,.,…]. Append 1 writes arr[3], calculates copied=2 using the old s=3, and copies indices 2 and 3. Now nextArr begins [2,6,8,1,…]. Since s=C, promote it to arr, create a capacity-16 preparation array, and set C=8. The new phase starts with s=C/2=4 and an empty copied prefix in the new nextArr.

Why does access work during preparation? arr remains complete throughout; partially copied nextArr is never used for reads. Why is promotion safe? By the phase invariant, all C elements have been copied before the old arr is released. Why do two copies suffice? There are C/2 appends between half-full and full, and 2×(C/2)=C copies. The algorithm initializes its first phase separately so the formula is never applied to empty arrays.

Every append executes a bounded number of reads, writes, arithmetic operations, and pointer assignments. Under the stated constant-time allocation and release model, it is Θ(1) worst-case. Access is one checked array read, also Θ(1). Peak storage is O(C)=O(s); even temporarily holding old, prepared, and fresh arrays adds only constant multiples.

This is a model-dependent guarantee. Real allocators may initialize storage or take variable time, and C++ object destruction can do work per element. The source explicitly idealizes allocation; use the corresponding simple raw-array model and constant-time release for this proof. Updating old items would require maintaining both copies correctly; that operation is outside this append/access-only contract.

Concept & explanation

7.1 A node contains data and a link

Concept · definition

A node is an object with fields. In a singly linked list, each node stores a value and a pointer called next. The next pointer holds the address of the following node. The list's head field points to the first node; NIL head represents an empty list.

Text diagram · source example
head = address 100
        |
        v
100: [value 4 | next 700]   700: [value 9 | next 250]
                              |
250: [value 2 | next NIL] <----+

Sequence view: head -> [4] -> [9] -> [2] -> NIL

Addresses need not be consecutive, and address order has no relation to sequence order. The link from 100 to 700 defines the successor. A tail pointer, when stored, points to the last node. It is extra information that can improve append, but not every operation at the tail.

In simple words

The book's p.next corresponds to C++ p->next when p is a node pointer. p ← p.next changes the local pointer p to reach another node; it does not move the original node. p.next ← q changes a field inside a node and therefore changes the list structure.

Concept & explanation

7.2 Aliasing and safe traversal

If q ← head, both pointers initially reach the same node. Updating q to q.next leaves head unchanged. Updating q.value changes the shared node's data. This distinction is aliasing: multiple names refer to one object.

Algorithm · pseudocode
PrintList(head):
    p ← head
    while p != NIL:
        print(p.value)
        p ← p.next
Runtime analysis

On 4→9→2, p reaches 4, then 9, then 2, then NIL. Each node is visited once: Θ(n) time and Θ(1) auxiliary space. Use a separate traversal pointer rather than advancing the only stored head and losing the start.

Bounds in this analysis: Θ(n), Θ(1)
Runtime analysis

To access index i, advance i links from head after validating the index. This takes Θ(i+1) time including the final read, and Θ(n) in the worst case. Unlike arrays, no arithmetic formula gives the address of the ith node.

Bounds in this analysis: Θ(i+1), Θ(n)
Concept & explanation

7.3 Inserting at the front

Algorithm · pseudocode
PushFront(head, x):
    q ← new Node(x, NIL)
    q.next ← head
    return q

head ← PushFront(head, 7)

The new node first points to the old first node. Returning q gives the caller the new head. Starting from 4→9, the result is 7→4→9. Starting from NIL gives 7→NIL. The work is constant under constant-time node allocation. A function that only assigns its own local head ← q without returning it or modifying a shared head field may fail to update the caller's head.

Concept & explanation

7.4 Inserting after a known node

Algorithm · pseudocode
InsertAfter(p, x):
    require p != NIL
    q ← new Node(x, NIL)
    q.next ← p.next
    p.next ← q

For 4→9→2, let p point to 9 and insert 7. First q.next remembers the node 2, then p.next is redirected to q. The result is 4→9→7→2. If the order were reversed, setting p.next=q first and then q.next=p.next would make q point to itself. The old suffix would be lost unless separately saved.

Runtime analysis

The update is Θ(1) when p is already available. If the request instead says “insert after index i,” locating p costs Θ(i+1). Include both search and update in the operation cost. If a tail field is maintained and p was the old tail, set tail=q too.

Bounds in this analysis: Θ(1), Θ(i+1)
Concept & explanation

7.5 Deletion and the predecessor

To delete the first node, save its value, save its next pointer as the new head, and release the old node. For deletion after a known predecessor p:

Algorithm · pseudocode
DeleteAfter(p):
    require p != NIL and p.next != NIL
    victim ← p.next
    result ← victim.value
    p.next ← victim.next
    release(victim)
    return result

In 4→9→7→2, with p at 9, this bypasses 7 and connects 9 directly to 2. Save needed fields before release. Following a released pointer is a use-after-free error. If victim was the tail, update the tail field to p.

Common mistake

A singly linked list does not directly reveal a node's predecessor. “Delete a known node in Θ(1)” is therefore not generally true under an identity-preserving contract. A trick that copies the successor's value cannot handle the last node and changes node identity; it is not a general substitute. Deleting by index or value may require Θ(n) traversal.

Concept & explanation

7.6 Appending and maintaining invariants

With both head and tail, append is simple: allocate q with q.next=NIL; if empty set both head and tail to q; otherwise set tail.next=q and tail=q. Each operation is Θ(1). Without tail, finding the last node requires Θ(n). With a singly linked list, removing the last node still requires finding its predecessor, so a tail pointer alone does not make pop-back constant-time.

Maintain these invariants: an empty list has head=tail=NIL; a nonempty tail has tail.next=NIL; following next from head reaches every live node exactly once. A cycle would make ordinary traversal fail to terminate. A doubly linked list adds a prev pointer to each node, making a known node's predecessor accessible, at the cost of more storage and more pointer updates. That is useful context; the supplied current list problems use singly linked lists.

Concept & explanation

7.7 Reversing links iteratively

Reversing a list means changing the sequence direction, not merely printing values backward. Save the unprocessed suffix before reversing each link:

Algorithm · pseudocode
Reverse(head):
    prev ← NIL
    curr ← head
    while curr != NIL:
        savedNext ← curr.next
        curr.next ← prev
        prev ← curr
        curr ← savedNext
    return prev

Concept & explanation

8.1 Recursion is a function call with a smaller job

Concept · definition

A recursive function calls itself. Each call has its own parameters and local variables. The machine does not replace the old call with the new call; it pauses the old one until the new one returns. This is the point that often makes recursion feel mysterious. There is no special leap of execution: there are ordinary calls, waiting work, and returns.

Imagine counting a row of people by asking the first person to count everyone behind them and then adding one. Eventually someone has nobody behind them and can answer directly. That direct answer is a base case. The request passed down the row is the recursive case. The row gets shorter, so the process reaches its base case.

A correct recursive definition needs a valid base case, a smaller input, a way to combine the smaller answer, and a guarantee of progress. Calling the function again on an unchanged input does not solve a smaller problem and generally causes nontermination.

Concept & explanation

8.2 The call stack

The call stack records active calls. A stack frame contains the current call's local information and where execution should continue after a nested call returns. The most recently started unfinished call returns first.

Algorithm · pseudocode
Factorial(n):
    require n ≥ 0
    if n == 0:
        return 1
    smaller ← Factorial(n−1)
    return n * smaller

For Factorial(3), calls descend as follows:

Algorithm · pseudocode
F(3): waits to multiply 3 by F(2)
  F(2): waits to multiply 2 by F(1)
    F(1): waits to multiply 1 by F(0)
      F(0): returns 1

Now returns unwind: F(1) receives 1 and returns 1; F(2) receives 1 and returns 2; F(3) receives 2 and returns 6. No multiplication is skipped. The value n=3 in the outer frame never becomes 2 merely because a new call receives 2.

There are n+1 calls including the base case. Each does constant work under a unit-cost arithmetic model, so time Θ(n) and maximum active frames Θ(n). Actual large factorial values require growing integer representations; the unit-cost model deliberately ignores that bit cost. Depth is the maximum number of simultaneously active frames, not necessarily the total number of calls in a branching algorithm.

Concept & explanation

8.3 A recursive design checklist

State a contract before writing code: what does the function return or change for any valid input? Then choose the smallest input that can be answered directly. Remove one item or split the input to make progress. Assume the smaller call fulfills its contract, and explain how to complete the larger job. This reasoning is closely related to mathematical induction.

For a list, the recursive structure is especially natural: a nonempty list is one head node followed by a smaller list. The recursive call can handle head.next. The main questions become what to do with head and whether that work belongs before or after the call.

Concept & explanation

8.4 Printing forward and backward

Algorithm · pseudocode
PrintForward(p):
    if p == NIL:
        return
    print(p.value)
    PrintForward(p.next)

PrintReverse(p):
    if p == NIL:
        return
    PrintReverse(p.next)
    print(p.value)

On 2→5→8, PrintForward prints 2, then calls on 5, prints 5, calls on 8, prints 8, and finally returns at NIL. PrintReverse first calls down to NIL without printing. Its waiting frames then print 8,5,2 as they return.

8.5 Summing and searching recursively

Algorithm · pseudocode
SumList(p):
    if p == NIL:
        return 0
    return p.value + SumList(p.next)

The empty list has sum 0; a nonempty list's sum is its first value plus the suffix sum. On 2→5→8 the return values are 0,8,13,15. This is a standard prerequisite example, not a reconstruction of the unspecified “add” function mentioned in [L].

For recursive search, return false at NIL, return true if p.value matches, and otherwise recurse on p.next. Unlike a full sum, a search can stop early. Its best time is Θ(1) for a first-node match and worst time Θ(n) for an absent target. The recursive stack follows the number of nodes actually visited.

Concept & explanation

8.6 Reversing the actual links recursively

The contract for ReverseRec(p) is: reverse the list beginning at p and return its new head. It may change next fields. The smallest lists, empty and one-node, already have the required order.

Algorithm · pseudocode
ReverseRec(p):
    if p == NIL or p.next == NIL:
        return p
    newHead ← ReverseRec(p.next)
    p.next.next ← p
    p.next ← NIL
    return newHead

Use short-circuit or: if p=NIL, do not evaluate p.next. In C++ the corresponding || has that short-circuit behavior. Without it, split the two base checks into separate statements.

Trace 2→5→8. The call on 8 returns 8. In the waiting call on 5, p.next still reaches 8. Setting p.next.next=p sets 8.next=5; setting p.next=NIL sets 5.next=NIL. The suffix is now 8→5→NIL and newHead is 8. In the outer call on 2, p.next still reaches the original next node 5. Setting 5.next=2 and 2.next=NIL creates 8→5→2→NIL.

Text diagram · source example
After reversing the suffix of 2:
newHead -> [8] -> [5] -> NIL
                    ^
p -> [2] -----------+   (p.next still reaches 5)

Attach 2 after 5, then cut 2's old outgoing link:
newHead -> [8] -> [5] -> [2] -> NIL

Cutting p.next is essential; otherwise the final two nodes point to each other and form a cycle. Returning newHead is essential; returning p would return the new tail. The function performs one recursive call on n−1 nodes and constant local pointer work, yielding T(n)=T(n−1)+Θ(1)=Θ(n). Stack space is Θ(n). A version that scans the reversed suffix to find its tail at every return can instead cost Θ(n²).

Concept & explanation

8.7 Combining two lists recursively

For interleaving, think in pairs of nodes. The desired result begins with a's first node, then b's first node, followed by the recursively interleaved suffixes. Save the next pointers before rewiring them. This contract-based pattern leads to the full [A2] solution in Chapter 16. The idea is different from sorted merging: alternation depends on source position, not which value is smaller.

If each input list has length n, removing one node from each makes the recursive size n−1. Even though the output contains 2n nodes, constant pointer work per pair yields Θ(n) time. Input-size definitions should be explicit so the recurrence is not mistaken for two recursive calls.

Concept & explanation

8.8 Recursion on arrays

Recursive algorithms can work on index intervals without copying arrays:

Algorithm · pseudocode
SumRange(A, lo, hi):
    if lo > hi:
        return 0
    if lo == hi:
        return A[lo]
    mid ← lo + (hi−lo) div 2
    return SumRange(A, lo, mid) + SumRange(A, mid+1, hi)

This makes two half-size calls, not one. For four elements [2,5,8,1], the calls split [0..3] into [0..1] and [2..3], then into four singleton intervals. The returned sums are 7 and 9, then 16. There are Θ(n) leaves and Θ(n) total calls, so time Θ(n), but depth only Θ(log n) for this balanced division. The two child calls run sequentially; their stack depths do not add because the first finishes before the second begins.

Passing index boundaries costs constant time. Physically copying a suffix or a slice can add nonconstant work to each call. For a one-item-at-a-time recursion, copying n−1 elements, then n−2, and so on creates Θ(n²) copying even if the conceptual logic visits each item once.

Concept & explanation

8.9 How to prove recursive correctness

For PrintReverse, prove the contract by list length. Base: the empty list prints nothing, its correct reverse order. Inductive step: assume the call on the n−1-node suffix prints that suffix backward. Printing the head afterward places it last, which is exactly the reverse of the whole n-node list. The recursive input strictly shrinks, so it reaches the base case. This separates correctness from runtime: “it visits n nodes” alone does not prove the output order.

For reversal, the smaller-call contract guarantees a correctly reversed suffix with its original first node now at the end. Attaching the original head there and cutting its old link produces exactly the whole reversed list. State what is returned, what is changed, and why no node is omitted or duplicated.

Concept & explanation

9.1 The sorting contract

Concept · definition

Sorting rearranges a sequence into nondecreasing order: each item is no larger than the next. The result must contain the same items with the same multiplicities. Returning [1,2] for [2,1,2] is not sorting because it loses a copy. In-place sorting changes the input array. A sort can also return a new array while preserving the original.

Concept · definition

A stable sort preserves the original relative order of records with equal keys. If two records have key 2 and labels a,b, stable output keeps 2a before 2b when that was their input order. Stability matters when sorting records by one field after another; numeric values alone conceal the distinction.

An in-place algorithm normally uses O(1) extra data storage, though some descriptions allow a logarithmic recursive call stack. State whether stack space is included. This chapter reports auxiliary space explicitly instead of relying on that potentially ambiguous label.

Concept & explanation

9.2 Insertion sort: place the next item in a sorted prefix

In simple words

Imagine sorting cards in your hand. Keep the left prefix sorted, take the next value, shift larger prefix values one position right, and put the new value in the gap.

Algorithm · pseudocode
InsertionSort(A, n):
    for i ← 1 to n−1:
        key ← A[i]
        j ← i−1
        while j ≥ 0 and A[j] > key:
            A[j+1] ← A[j]
            j ← j−1
        A[j+1] ← key

The Boolean condition short-circuits: when j<0, do not read A[j]. key must be saved before shifting; otherwise the first shift can overwrite the value being inserted. j+1 is the gap immediately after the last item no greater than key, or index 0 if every prefix item was larger.

Complete trace on [4,1,3,2]:

i and key Shifts Array after insertion
i=1, key=1 Move 4 from 0 to 1 [1,4,3,2]
i=2, key=3 Move 4 from 1 to 2 [1,3,4,2]
i=3, key=2 Move 4, then 3, right [1,2,3,4]

Before each iteration A[0..i−1] is sorted and contains the original prefix items. Shifting and inserting key extends that sorted prefix to include i. After the last iteration it covers the whole array, establishing correctness.

Runtime analysis

For already sorted input, no values shift; each iteration makes a bounded amount of work, giving Θ(n) best-case time. For reverse-sorted distinct input, insertion i shifts i items, so total shifts are 1+2+…+(n−1)=Θ(n²). For uniformly random permutations of distinct keys, about half the earlier keys exceed a typical key, giving Θ(n²) average time. Auxiliary space is Θ(1). Using > rather than ≥ preserves equal-key order, so this version is stable.

Bounds in this analysis: Θ(n), Θ(n²), Θ(1)
Concept & explanation

9.3 Selection sort: select the next minimum

Rather than insert a new item into a sorted prefix, selection sort scans the remaining suffix to find its minimum, then swaps it into the next output position.

Algorithm · pseudocode
SelectionSort(A, n):
    for i ← 0 to n−2:
        smallest ← i
        for j ← i+1 to n−1:
            if A[j] < A[smallest]:
                smallest ← j
        swap(A[i], A[smallest])

On [4,1,3,2], the first scan selects 1 and swaps it with 4, yielding [1,4,3,2]. The second selects 2 and swaps with 4, yielding [1,2,3,4]. The third scans [3,4], selects 3, and changes nothing. The sorted prefix contains the smallest items in order; selecting the next minimum preserves that fact.

Runtime analysis

Comparisons always total (n−1)+(n−2)+…+1=n(n−1)/2, regardless of initial order. Best, average, and worst time are Θ(n²); swaps are only O(n). Auxiliary space is Θ(1). This swapping version is generally unstable: [2a,2b,1] becomes [1,2b,2a] after the first swap. Few swaps do not imply few comparisons.

Bounds in this analysis: Θ(n²), Θ(1)
Concept & explanation

9.4 Bubble sort: move large values right by adjacent swaps

Bubble sort repeatedly compares neighbours. If the left value is larger, swap them. After a full pass, the maximum of the active region has reached its right end. The next pass can stop before that fixed position.

Algorithm · pseudocode
BubbleSort(A, n):
    for end ← n−1 downto 1:
        changed ← false
        for j ← 0 to end−1:
            if A[j] > A[j+1]:
                swap(A[j], A[j+1])
                changed ← true
        if not changed:
            return

Complete comparison trace on [4,1,3,2]: first pass swaps 4 with 1 to get [1,4,3,2], then 4 with 3 to get [1,3,4,2], then 4 with 2 to get [1,3,2,4]. Second pass leaves 1,3 in order and swaps 3,2, producing [1,2,3,4]. Third pass compares 1,2, makes no swap, and returns.

Runtime analysis

The fixed suffix is sorted after each pass and all its items are at least the active prefix's items. If a pass changes nothing, all neighbouring pairs in the active region are ordered, so no further work is needed. The early-stop version takes Θ(n) on already sorted input. Reverse order needs Θ(n²) comparisons/swaps; uniformly random distinct permutations also give Θ(n²) average time. Without early stopping, even sorted input takes Θ(n²). Strict comparisons make adjacent equal records stay ordered, so this version is stable. Extra space is Θ(1).

Bounds in this analysis: Θ(n), Θ(n²), Θ(1)
Concept & explanation

9.5 Merging two sorted sequences

Merging is a separate algorithm used by merge sort. If both input lists of values are sorted, the smaller of their first unconsumed values must be the next output. When one input is exhausted, copy the other's remainder.

Algorithm · pseudocode
Merge(L, R):
    i ← 0; j ← 0; out ← empty array
    while i < length(L) and j < length(R):
        if L[i] ≤ R[j]:
            append L[i] to out
            i ← i+1
        else:
            append R[j] to out
            j ← j+1
    append all remaining L items to out
    append all remaining R items to out
    return out
Runtime analysis

The append operations here use preallocated output space or amortized constant-time append; preallocation gives a direct worst-case bound. For L=[1,4] and R=[2,3], choose 1, then 2, then 3, then copy 4. The output is [1,2,3,4]. i and j only move forward; each of p+q items is written once, so time Θ(p+q). There are at most p+q−1 comparisons between the two input heads when both inputs are nonempty. Taking from L on ties preserves stability across the two halves.

Bounds in this analysis: Θ(p+q)
Concept & explanation

9.6 Merge sort: sort halves, then merge

Algorithm · pseudocode
MergeSort(A):
    if length(A) ≤ 1:
        return A
    mid ← length(A) div 2
    L ← MergeSort(copy of A[0..mid−1])
    R ← MergeSort(copy of A[mid..length(A)−1])
    return Merge(L, R)

This teaching version explicitly makes slices; their total copying per recursion level is Θ(n), which fits merge sort's bound. An indexed implementation can use a single reusable output buffer and avoid repeated allocations.

Complete trace: [4,1,3,2] splits into [4,1] and [3,2]; those split into [4],[1],[3],[2]. Merge [4] with [1] to get [1,4]. Merge [3] with [2] to get [2,3]. Merge those results by choosing 1,2,3,4. The base case is sorted; assuming the recursive halves are sorted, Merge produces a sorted permutation of all items. This is the correctness induction.

Runtime analysis

Time satisfies T(n)=2T(n/2)+Θ(n), with constant-size base work. Each of about log₂ n levels handles Θ(n) total data, so T(n)=Θ(n log n) in best, average, and worst cases for this version. Standard array merge sort uses Θ(n) auxiliary data storage and Θ(log n) call-stack depth. If recursion is depth-first and temporary arrays are released appropriately, peak live storage remains O(n), even though cumulative allocation can exceed n. It is stable with the tie rule above.

Bounds in this analysis: Θ(n), Θ(n log n), Θ(log n)
Concept & explanation

9.7 Quicksort and in-place partition

Quicksort puts a pivot into its final sorted position, with smaller/equal values to one side and larger values to the other. It then sorts those sides independently. Partitioning need not fully sort either side.

Use a concrete Lomuto partition with the last element as pivot:

Algorithm · pseudocode
Partition(A, lo, hi):
    pivot ← A[hi]
    i ← lo−1
    for j ← lo to hi−1:
        if A[j] ≤ pivot:
            i ← i+1
            swap(A[i], A[j])
    swap(A[i+1], A[hi])
    return i+1

QuickSort(A, lo, hi):
    if lo ≥ hi:
        return
    p ← Partition(A, lo, hi)
    QuickSort(A, lo, p−1)
    QuickSort(A, p+1, hi)

During partition, A[lo..i] contains processed values ≤pivot; A[i+1..j−1] contains processed values >pivot; A[j..hi−1] is unprocessed. Advancing i and swapping a qualifying item extends the first region. After scanning, swapping the pivot into i+1 separates the regions correctly.

Complete quicksort trace on [4,1,3,2]: pivot=2. At j=0, 4 is too large, so no change. At j=1, 1 qualifies; i becomes 0 and swapping gives [1,4,3,2]. At j=2, 3 is too large. The final pivot swap gives [1,2,3,4] with p=1. The left singleton [1] needs no work. Partition [3,4] with pivot 4 leaves it ordered and returns its final index; the remaining subranges are singletons or empty. Even though this small partition happened to leave the entire array sorted, partition is not generally a complete sort.

Runtime analysis

Partition takes Θ(m) for a subarray of length m. Balanced divisions yield T(n)=2T(n/2)+Θ(n)=Θ(n log n). Repeatedly choosing an extreme key yields T(n)=T(n−1)+Θ(n)=Θ(n²). Last-element pivots on already sorted distinct arrays are a standard worst-case example. For uniformly random pivot ranks on distinct keys, expected time is Θ(n log n); randomized choice does not remove the possibility of Θ(n²) time on a particular run. Balanced/expected stack depth is logarithmic in the usual analysis; naive worst-case depth is Θ(n). Partition itself needs Θ(1) extra storage. This swapping quicksort is not stable.

Bounds in this analysis: Θ(m), Θ(n), Θ(n log n), Θ(n²), Θ(1)
Common mistake

Many equal keys can also make this two-way partition highly unbalanced, even with randomized pivots. A three-way partition separates less/equal/greater regions, but that is an extension. Runtime claims must match the actual partition and duplicate-key assumptions.

Concept & explanation

9.8 Why comparison sorting has a lower bound

A comparison sort learns relative order through comparisons of keys. Insertion, selection, bubble, merge, and quicksort are comparison sorts. For n distinct keys there are n! possible input orders. A comparison decision tree must distinguish those orders to produce the right sorted permutation.

With binary outcomes for distinct keys, a tree of height h has at most 2h leaves. Therefore 2h≥n!, so h≥log₂(n!)=Ω(n log n), using Chapter 3's log-sum bound. Some input must require that many comparisons. This is a worst-case lower bound in the comparison model, not an upper bound and not a ban on specialized integer sorting. Merge sort's Θ(n log n) worst-case comparison time matches the lower-bound order.

Concept & explanation

9.9 Counting sort: use bounded integer keys

Suppose keys are integers 0..k−1. Count how many times each key appears, then use those counts to place records. A simple frequency output works for plain integers; a stable version is valuable for radix sort.

Algorithm · pseudocode
StableCountingSort(A, n, k):
    C[0..k−1] ← all zeros
    B[0..n−1] ← new output array
    for each record x in A:
        C[key(x)] ← C[key(x)] + 1
    for v ← 1 to k−1:
        C[v] ← C[v] + C[v−1]
    for i ← n−1 downto 0:
        v ← key(A[i])
        C[v] ← C[v]−1
        B[C[v]] ← A[i]
    return B

After prefix summation, C[v] is the number of keys ≤v, the exclusive end position for that key's output group. Decrementing produces a valid zero-based slot. Scanning input backward places later equal-key records later in output, preserving stability.

Complete trace on [4,1,3,2], k=5: frequencies C=[0,1,1,1,1]; prefix counts [0,1,2,3,4]. Process input backward: put 2 in B[1], 3 in B[2], 1 in B[0], and 4 in B[3]. Result [1,2,3,4]. The grouped placement is the whole sorting process, not repeated comparisons.

Initializing and prefix-summing k counters costs Θ(k); reading and writing n records costs Θ(n). Total Θ(n+k), extra space Θ(n+k). It is linear in n only when k=O(n), or a fixed small range. If keys include negatives, an offset can map a known bounded interval to nonnegative counters; the interval width still matters. Allocating n999 counters would not meet O(n).

Concept & explanation

9.10 Radix sort: process digits stably

An integer can be represented using digits in a base b. Decimal 213 has digits 2,1,3; in base b, digit position p is (x div b^p) mod b. Least-significant-digit radix sort stably sorts by the last digit, then the next, and so on. Stability preserves the order already established by lower digits within an equal higher-digit group.

Algorithm · pseudocode
RadixSort(A, d, b):
    place ← 1
    for p ← 0 to d−1:
        A ← stable counting sort by (x div place) mod b
        if p < d−1:
            place ← place*b
    return A

Complete decimal trace on [21,13,12,3], treating 3 as 03: units digits 1,3,2,3 produce [21,12,13,03], preserving 13 before 03 within digit 3. Tens digits 2,1,1,0 then produce [03,12,13,21]. After the first pass the last digit is ordered. Inductively, stable sorting by the next digit orders the entire processed suffix of digits. After d passes all digits are considered, so the full keys are sorted.

Each pass costs Θ(n+b) with counting sort, giving Θ(d(n+b)) time and Θ(n+b) working storage reused across passes. Fixed decimal width means constant d only if the key bound is fixed accordingly. For keys in [0,n999] and n≥2, base n gives at most 1000 digits, including the endpoint n999. Then b=n and d≤1000 are sufficient, so time O(n) under unit-cost digit extraction on suitably sized words. The constant is large, but it does not depend on n. Chapter 16 uses this carefully in [A2]'s minimum-difference problem.

Runtime analysis

10.1 Translate an algorithm into an equation

A recurrence defines a quantity using smaller instances of itself. T(n) denotes the runtime on size n. If a list algorithm makes one call on n−1 nodes and performs constant local work, write T(n)=T(n−1)+Θ(1), with T(0)=Θ(1). The equation counts the smaller call and the work done outside it.

Merge sort makes two calls on about n/2 elements and merges in Θ(n), giving T(n)=2T(n/2)+Θ(n). Binary search makes only one half-size call, giving T(n)=T(n/2)+Θ(1). Halving an input does not by itself imply logarithmic total time: the number of branches and local work matter.

When n is not a convenient power of b, floors, ceilings, and constant-size bases usually preserve the standard bounds, but the code must still terminate. For tree calculations, first assume n=bh; then check that rounding does not change the growth order.

Runtime analysis

10.2 Unrolling simple recurrences

For T(n)=T(n−1)+c, substitute repeatedly: T(n)=T(n−2)+2c=…=T(0)+nc. Hence Θ(n). For T(n)=T(n−1)+n, the added work is n+(n−1)+…+1, giving Θ(n²). The reduction is by one, so neither fits the usual Master theorem.

For T(n)=T(n/2)+c, after t substitutions the input is n/2t. It reaches 1 when t=log₂ n. There is constant work at each of those levels, giving Θ(log n). For T(n)=T(n/2)+n, the work is n+n/2+n/4+…=Θ(n), even though depth remains logarithmic.

These derivations are useful even when a theorem is available: they explain why a theorem's result makes sense and expose wrong recurrence setup.

Runtime analysis

10.3 Recursion-tree accounting

For T(n)=aT(n/b)+f(n), a is the number of recursive children and n/b is each child's size. At level j there are aj subproblems of size n/bj. Local work at that level is aj f(n/bj). Height is approximately log_b n. The number of leaves is alog_b n=nlog_b a.

For f(n)=nd, the level cost is nd(a/bd)j, a geometric series. If a/bd<1, upper levels dominate. If it equals 1, every level has the same order and an extra log n appears. If it exceeds 1, lower levels and leaves dominate. The critical exponent is p=log_b a, where bp=a.

10.4 The basic three-case Master theorem

Assume T(n)=aT(n/b)+f(n), a≥1, b>1 are constants, f is eventually nonnegative, and base cases cost Θ(1). Let p=log_b a. The following is a standard basic version; the exact classroom/textbook statement was not supplied.

Scroll horizontally to read every column →

Case Requirement Conclusion
1: leaf dominated f(n)=O(np−ε) for some fixed ε>0 T(n)=Θ(np)
2: balanced f(n)=Θ(np) T(n)=Θ(np log n)
3: root dominated f(n)=Ω(np+ε) for some fixed ε>0, plus regularity T(n)=Θ(f(n))

Case 3's regularity condition is a f(n/b)≤c f(n) for some fixed c<1 and all sufficiently large n. It ensures costs decrease geometrically away from the root. The polynomial gap ε in cases 1 and 3 is essential: a factor log n is not a polynomial gap.

An efficient checklist is: verify the recurrence shape; identify a,b,f; compute p; compare f to np; check a fixed-power gap or balanced condition; check regularity if using case 3; then state the result. Do not select a case by visually guessing that f is “a little bigger.”

Worked example

10.5 Worked examples of the basic cases

For T(n)=4T(n/2)+n, a=4,b=2,p=2. Since n=O(n2−1), case 1 gives Θ(n²). The many leaf calls dominate the linear top-level work.

For T(n)=2T(n/2)+n, p=1 and f=n matches np. Case 2 gives Θ(n log n). This is merge sort: n work across each of log n levels.

For T(n)=2T(n/2)+n², p=1 and f=n² has a polynomial gap ε=1. Regularity gives 2(n/2)²=n²/2, so c=1/2 works. Case 3 gives Θ(n²). Adding every level's work forms n²+n²/2+n²/4+… .

For T(n)=T(n/3)+n², p=0. The quadratic work has a polynomial gap over 1, and f(n/3)=n²/9 satisfies regularity. Thus Θ(n²), not Θ(log n). The depth is logarithmic, but the root alone does quadratic work.

Runtime analysis

10.6 A common logarithmic extension

Many courses extend the balanced case to f(n)=Θ(np(log n)k), for a fixed k≥0. That version gives:

T(n)=Θ(np(logn)k+1).T(n)=Θ(np(log n)k+1).

At level j, the critical np factor stays constant across the level and the remaining log factor depends on the levels left. Summing those powers across log n levels adds one power of log n. For example T(n)=4T(n/2)+n² log n has p=2,k=1, so Θ(n² log² n).

The sample recurrence T(n)=16T(n/4)+n² log² n has p=2 and k=2. It is not covered by the narrow balanced requirement f=Θ(n²), and log² n does not supply a polynomial gap for case 3. Under the stated logarithmic extension, the result is Θ(n² log³ n). Therefore a course asking “does the Master theorem apply?” needs the exact version. This book labels the distinction instead of inventing what was taught.

Some stronger formulations also handle negative log powers. They are not included in the k≥0 extension just stated. For instance T(n)=2T(n/2)+n/log n, with small-size base cases avoiding log 1, has level costs approximately n/(log n−j); summing them gives Θ(n log log n). This follows from a harmonic sum, not from setting k=−1 in the k≥0 formula. A theorem's restrictions are part of its statement.

Runtime analysis

10.7 Polynomial gaps versus logarithmic factors

Consider T(n)=3T(n/2)+n²/log n, one of [S25]'s examples. Here p=log₂3≈1.585. Although dividing n² by log n reduces growth, f still exceeds np+ε for a sufficiently small fixed ε>0. Choose ε=(2−p)/2; a positive power of n eventually exceeds log n, which supplies the gap.

For regularity, 3 f(n/2)/f(n)=(3/4)log n/log(n/2), which tends to 3/4. Hence it is eventually bounded by a constant below 1. Basic case 3 applies and gives Θ(n²/log n). Do not reject the theorem merely because a logarithm appears: test the actual conditions.

Runtime analysis

10.8 When the theorem does not apply

T(n)=T(n−1)+n reduces by subtraction rather than a fixed ratio. T(n)=T(n/3)+T(2n/3)+n has unequal child sizes. T(n)=nT(n/2)+n has a nonconstant branching factor. None has the standard a,b shape. They may still be solved by unrolling, recursion trees, substitution, or stronger theorems; “not covered” does not mean “no solution exists.”

Even a matching shape may lie between the listed cases. T(n)=2T(n/2)+n log n fails the narrow basic cases but fits the k≥0 extension. T(n)=2T(n/2)+n/log n fails both versions as stated. A case-3 claim without checking regularity may also be unjustified.

Runtime analysis

10.9 Correctness of a guessed bound

Unrolling can suggest a bound; substitution can verify it. For T(n)=T(n−1)+n and T(0)=0, guess T(n)=n(n+1)/2. Assuming the formula for n−1, substitute: T(n)=(n−1)n/2+n=n(n+1)/2. The base also matches. This proves the exact solution by induction.

For asymptotic guesses, retain enough slack in constants and lower-order terms to make the induction work. You need not force every recurrence into the Master theorem. The primary job is to count the algorithm's actual work correctly.

Concept & explanation

11.1 Searching asks a specific question

Search may ask whether a target exists, where it occurs, or where it should be inserted. With duplicates, “an occurrence” and “the first occurrence” are different contracts. A sorted array provides information about uninspected items; an unsorted array ordinarily does not.

Algorithm · pseudocode
LinearSearch(A, n, x):
    for i ← 0 to n−1:
        if A[i] == x:
            return i
    return NOT_FOUND

The first matching position is returned. If the target is absent, all n positions are checked. Best time Θ(1), worst Θ(n); if a present target's position is uniformly distributed, the expected number of comparisons is (n+1)/2=Θ(n). That average claim depends on its position model.

Sorting once can be worthwhile when many searches follow, but sorting for only one query may cost more than scanning. With q searches, ordinary scanning costs O(qn); comparison sorting once and binary searching each costs O(n log n+q log n), ignoring update costs. Choose based on the workload, not only the cost of one search after preprocessing.

Concept & explanation

11.2 Binary search intuition

In sorted [2,5,8,12,16,23], inspecting a middle value tells us about an entire side. If target=16 and the middle is 8, every value at or left of that middle is ≤8, so none equals 16. Discarding that side is justified by order. In unsorted [16,2,8,23,5,12], the same discard could throw away the target.

Maintain an inclusive interval [lo..hi] in which a match could still exist. At each iteration inspect its middle, return on equality, or remove the middle and the impossible side.

Algorithm · pseudocode
BinarySearch(A, n, x):
    lo ← 0
    hi ← n−1
    while lo ≤ hi:
        mid ← lo + (hi−lo) div 2
        if A[mid] == x:
            return mid
        if A[mid] < x:
            lo ← mid+1
        else:
            hi ← mid−1
    return NOT_FOUND

lo+(hi−lo) div 2 avoids the possible overflow of lo+hi in machine arithmetic. Updating to mid+1 or mid−1 removes the tested position and ensures progress. Setting lo=mid with this loop can leave a one-element interval unchanged forever.

Each unsuccessful iteration at least halves the candidate count up to rounding, so worst time is Θ(log n) for growing n; best is Θ(1) if the first middle matches. Iterative auxiliary space is Θ(1). A recursive version has Θ(log n) worst-case stack depth.

Concept & explanation

11.4 First occurrence and insertion position

Binary search above can return any matching duplicate. To find the first position whose value is at least x, use a different invariant and a half-open interval [lo,hi), where hi is excluded:

Algorithm · pseudocode
LowerBound(A, n, x):
    lo ← 0; hi ← n
    while lo < hi:
        mid ← lo + (hi−lo) div 2
        if A[mid] < x:
            lo ← mid+1
        else:
            hi ← mid
    return lo

Values before lo are known to be <x; values at or after hi are known to be ≥x. At termination the boundary is lo. It may equal n, meaning all values are smaller. To test existence, check lo<n and A[lo]==x in that order. On [1,3,3,3,8] with x=3, boundaries shrink from [0,5) to [0,2) to [0,1) to [1,1), returning 1. This variant intentionally uses hi=mid because the middle could be the desired first boundary. Do not mix its conditions with the inclusive equality-search template.

Concept & explanation

11.5 Modified binary search for a valley

[A2] gives an array that strictly decreases and then strictly increases. The minimum lies at the valley. The values are not globally ascending, so searching by comparing a target with A[mid] is not appropriate. Instead compare neighbouring values to determine the local slope.

Algorithm · pseudocode
ValleyMinimumIndex(A, n):
    require n ≥ 1 and the stated decreasing/increasing shape
    lo ← 0; hi ← n−1
    while lo < hi:
        mid ← lo + (hi−lo) div 2
        if A[mid] > A[mid+1]:
            lo ← mid+1
        else:
            hi ← mid
    return lo

When lo<hi, mid<hi, so mid+1 is valid. If A[mid]>A[mid+1], the array is still descending there, so the minimum is strictly right of mid. Otherwise it is ascending there and the minimum is at mid or left of it. Each update preserves the minimum inside the interval. Strictness excludes a flat plateau that would need different reasoning.

Complete [A2] trace on [10,8,3,1,5,11,20,30,40]: [0,8] gives mid=4 and 5<11, so hi=4; [0,4] gives mid=2 and 3>1, so lo=3; [3,4] gives mid=3 and 1<5, so hi=3. Return zero-based index 3. The university example returns one-based index 4, the same element. A loop halves the interval, so Θ(log n) time, Θ(1) auxiliary space. The source assumes at least three elements; this code also handles smaller inputs under its stated shape contract.

Concept & explanation

11.6 Selection is about rank

The kth smallest value is defined by sorted position, not numeric value. This book uses zero-based rank k: k=0 is the minimum, k=n−1 the maximum. Sorting and returning A[k] works in O(n log n) comparison time, but finding one rank does not require fully sorting every side.

Quickselect uses Chapter 9's partition. After partition returns p, A[p] is at its final sorted position within the active interval. If k=p, return it. If k<p, only the left side can contain rank k; otherwise only the right side can. Unlike quicksort, select recurses into just one side.

Algorithm · pseudocode
Quickselect(A, lo, hi, k):
    require lo ≤ k ≤ hi
    if lo == hi:
        return A[lo]
    choose a pivot, move it to A[hi]
    p ← Partition(A, lo, hi)
    if k == p:
        return A[p]
    if k < p:
        return Quickselect(A, lo, p−1, k)
    return Quickselect(A, p+1, hi, k)

Since k is a global array index, it is unchanged when going right. A variant using rank relative to a copied subarray must subtract the discarded left size and pivot; mixing those conventions is a common error.

Concept & explanation

11.7 Quickselect trace and runtime

Find zero-based rank 2, the third smallest, in [7,2,9,4,1], using last pivots for a reproducible trace. Partition at pivot 1 swaps it to index 0, producing [1,2,9,4,7]; k=2 is to the right. Partition indices 1..4 with pivot 7: 2 and 4 qualify, yielding [1,2,4,7,9] with p=3. k=2 is now left of that pivot, so examine indices 1..2. Partition at 4 returns p=2 and value 4. The output value is correct even though selection need not generally leave the full array sorted.

If the retained side is consistently at most a fixed fraction, the work is n+n/2+n/4+…=Θ(n), or another comparable geometric sum. Random uniform pivots on distinct keys give expected Θ(n) time: a constant fraction of pivots lie in the middle half, and each such pivot reduces the retained size to at most about 3n/4; the expected waiting for that progress is constant. Bad pivots can instead leave n−1 elements each time, giving Θ(n²) worst time. Randomized expected performance is not a deterministic worst-case guarantee. An iterative version keeps Θ(1) extra storage; recursive stack depth can be Θ(n) in the worst case.

Concept & explanation

12.1 The most recent unfinished item comes first

Concept · definition

A stack behaves like a pile of plates: add a plate on top, and the top plate is the one you can remove. LIFO means last in, first out. It describes removal order, not how values compare numerically. Pushing 8 then 2 makes 2 the next removed value even though 8 is larger.

push(x) adds x, pop() removes and returns the top item, peek() returns it without removal, and isEmpty() tests whether no items remain. Pop and peek on an empty stack require a stated error or special result; they must not read an invalid slot.

Text diagram · source example
push(4), push(9), push(2)

top -> [2]      pop returns 2
       [9]      next pop would return 9
       [4]

After pushing 4,9,2, peeking returns 2 and leaves all three items. Popping returns 2 and leaves 4,9 with 9 at the top. A stack is not a set: duplicate pushes create duplicate items.

Concept & explanation

12.2 Array implementation

Let s be the number of stored items, and use A[0..s−1] as the live stack. The top is at index s−1. This book does not use a top variable that sometimes means size and sometimes means last index.

Algorithm · pseudocode
Push(x):
    if s == capacity:
        grow array or report FULL
    A[s] ← x
    s ← s+1

Pop():
    if s == 0:
        report EMPTY
    s ← s−1
    return A[s]

Peek():
    if s == 0:
        report EMPTY
    return A[s−1]

Pop decrements size before reading the old top slot; the new size is exactly that slot's index. Stale values outside the live prefix are not stack contents. A fixed-capacity push/pop/peek takes Θ(1) if the operation is valid. With ordinary doubling, push is Θ(1) amortized and Θ(s) worst-case when growing. Pop without shrinking remains Θ(1). Do not call a resizing stack's push unconditionally worst-case constant-time.

Concept & explanation

12.3 Linked-list implementation

Use the head as the top. Push allocates a node whose next points to the old head, then replaces head. Pop saves head.value, advances head to head.next, releases the removed node, and returns its value. Peek reads head.value after checking head!=NIL. Every valid operation performs bounded pointer work, so Θ(1) under constant-time node allocation/release. No tail pointer is needed.

Using the tail of a singly linked list as the top is usually a poor choice: popping the tail requires finding its predecessor. The abstract stack behavior is identical, but its implementation cost changes. Put the frequently updated end where the representation makes it easy.

Algorithm · pseudocode
LinkedPush(x):
    q ← new Node(x, head)
    head ← q

LinkedPop():
    if head == NIL:
        report EMPTY
    old ← head
    answer ← old.value
    head ← old.next
    release(old)
    return answer

These operations update a shared stack object's head field. If head is instead a local function parameter, return the changed head together with any popped value. The fields returned or changed are part of the interface, not a language detail that can be ignored.

12.5 Stacks store postponed work

Recursion uses a call stack because the most recently started call must finish before its caller can continue. Undo histories and expression processing also naturally remove the latest unfinished action. A stack can print a linked list in reverse: traverse forward, push every value, then pop and print until empty. This takes Θ(n) time and Θ(n) extra storage. It reverses the output order but leaves node links unchanged.

To reverse links with a stack of node pointers, first push all nodes. Pop the last node as newHead, repeatedly link the current node to the next popped node, and finally set the last node's next=NIL. Omitting that final cut can create a cycle. This method is Θ(n) time and Θ(n) extra space; Chapter 7's three-pointer method achieves Θ(1) extra space.

Concept & explanation

13.1 First in, first out

Concept · definition

A queue behaves like a line at a service desk: arrivals join the back and departures leave the front. FIFO means first in, first out. enqueue(x) adds at the back, dequeue() removes and returns the front, and frontValue() inspects the front without removing it.

Enqueue 4,9,2 and the next dequeue returns 4, leaving 9,2. A stack on the same insertion sequence would return 2. Neither sorts the values. Their interfaces impose different removal orders.

Concept & explanation

13.2 Why a shifting array is inefficient

If a queue always stores its front at A[0], removing it shifts every remaining item left. That makes dequeue Θ(n). Leaving the other items in place and advancing a front index avoids shifting, but eventually the index reaches the array's right end even if earlier positions are now free.

A circular array reuses those free slots by wrapping an index back to 0. The storage is still an ordinary array; the circle is a rule for interpreting indices. For capacity C, the slot after i is (i+1) mod C.

Concept & explanation

13.3 One explicit full/empty convention

Store capacity C>0, front index f, and size s. The front item, when any, is A[f]. The next insertion slot is (f+s) mod C. Empty means s=0; full means s=C. This uses all C slots and avoids ambiguity when front and next-insertion indices coincide.

Algorithm · pseudocode
Enqueue(x):
    if s == C:
        report FULL
    backSlot ← (f+s) mod C
    A[backSlot] ← x
    s ← s+1

Dequeue():
    if s == 0:
        report EMPTY
    result ← A[f]
    f ← (f+1) mod C
    s ← s−1
    return result

Initialization is f=0,s=0. The kth logical item is A[(f+k) mod C] for 0≤k<s. This representation invariant explains why no shifting is needed. Enqueue writes just after the last logical item. Dequeue skips exactly the first logical item. Both preserve order and take Θ(1) time for a fixed-capacity queue.

Another common convention stores only head and tail indices and leaves one slot empty, so usable capacity is C−1. That is valid but different. Do not combine its full test with the size-based representation. [S25]'s capacity-5 sequence reaches five live items, so using all slots with a size field is especially convenient for that trace.

13.5 Resizing a circular queue

If growth is permitted when full, allocate a larger array B, then copy the kth logical item to B[k] for k=0..s−1. Set f=0 and replace the capacity. Copying the physical array without rotating the logical order can scramble the queue.

Algorithm · pseudocode
for k ← 0 to s−1:
    B[k] ← A[(f+k) mod C]
f ← 0
A ← B
C ← newCapacity

One resizing enqueue costs Θ(s); doubling gives Θ(1) amortized enqueue over many additions, under the same geometric reasoning as dynamic arrays. Fixed-capacity queue operations are worst-case Θ(1) only when invalid full/empty operations are handled without resizing.

Concept & explanation

13.6 Linked-list queue

Store both head and tail. Enqueue creates a node q with q.next=NIL. If empty, set head=tail=q; otherwise tail.next=q and tail=q. Dequeue removes head and advances it. If the removal makes head=NIL, also set tail=NIL. Forgetting the tail reset leaves a pointer to a released node and can corrupt the next enqueue.

Both enqueue and dequeue are Θ(1) under constant-time node allocation/release. A head-only singly linked representation needs Θ(n) to find the tail for enqueue. Adding a tail pointer improves precisely that operation.

Algorithm · pseudocode
LinkedEnqueue(x):
    q ← new Node(x, NIL)
    if head == NIL:
        head ← q
    else:
        tail.next ← q
    tail ← q

LinkedDequeue():
    if head == NIL:
        report EMPTY
    old ← head
    answer ← old.value
    head ← old.next
    if head == NIL:
        tail ← NIL
    release(old)
    return answer

For a singleton queue holding 7, dequeue saves 7, advances head to NIL, resets tail to NIL, and returns 7. Enqueue 9 afterward sees an empty head, sets head to the new node, and sets tail to that same node. This explicit transition tests the boundary that a longer queue trace can miss.

Concept & explanation

14.1 Balanced delimiters are nested promises

An opening parenthesis promises that a matching closing parenthesis will appear after its contents. The latest unfinished opening must close first. That is LIFO, which suggests a stack. Counting openings and closings alone is insufficient: )( has equal counts but the wrong order, and ([)] crosses nesting types.

Algorithm · pseudocode
Balanced(tokens):
    S ← empty stack
    for each token t:
        if t is one of (, [, {:
            S.push(t)
        else if t is one of ), ], }:
            if S.isEmpty():
                return false
            opening ← S.pop()
            if opening does not match t:
                return false
    return S.isEmpty()

Other tokens can be ignored when checking an expression. The stack holds exactly the unmatched openings in encounter order, newest on top. A closing must match its top; an unmatched closing fails immediately. At the end, a nonempty stack means missing closings.

Trace [()]: push [, push (, pop ( on ), pop [ on ], ending empty. Trace [(]): push [, push (, then ] expects [ but sees (, so reject. Each token is processed once, giving Θ(n) time. At most n openings may wait, so O(n) extra space; deeply nested input makes this Θ(n). For one parenthesis type alone, a counter can suffice, but a stack preserves types and nesting information for several delimiters.

Concept & explanation

14.2 Expressions have several notations

An operand is a value; an operator combines values. In infix, the operator sits between operands: 3+4. In postfix, it follows them: 3 4 +. In prefix, it precedes them: + 3 4. Postfix and prefix encode grouping without parentheses when each operator's arity is known.

For (2+3)*4, infix uses parentheses to require addition first. Postfix is 2 3 + 4 *; prefix is * + 2 3 4. Token boundaries matter: 12 3 + contains the number 12, not separate operands 1 and 2. The examples here use binary operators and already-tokenized numbers. Unary minus, function calls, and implicit multiplication require additional grammar rules and are not silently handled by this simplified algorithm.

Worked example

14.3 Postfix evaluation

Read left to right. Push each operand. When an operator appears, its two operands are the most recently completed values. Pop the right operand first and the left operand second; this order matters for subtraction and division.

Algorithm · pseudocode
EvaluatePostfix(tokens):
    S ← empty stack
    for t in tokens:
        if t is a number:
            S.push(t)
        else:
            require S has at least 2 values
            right ← S.pop()
            left ← S.pop()
            S.push(Apply(t, left, right))
    require S has exactly 1 value
    return S.pop()

For 2 3 + 4 * 6 2 / −, the stack states bottom-to-top are [2], [2,3], [5], [5,4], [20], [20,6], [20,6,2], [20,3], [17]. This evaluates (2+3)*4−6/2=17. Expressions here use ordinary arithmetic division; division by zero is invalid. In an integer-evaluation language, explicitly state truncation rules.

The invariant is that the stack holds values of fully processed subexpressions whose enclosing operations have not yet been completed. Each token causes a bounded number of stack operations, so Θ(n) time and O(n) space for n tokens, assuming constant-time arithmetic. Too few operands or more than one final value signals an invalid expression.

Concept & explanation

14.4 Precedence and associativity

Precedence says which operator binds more tightly: multiplication/division precede addition/subtraction. Associativity decides grouping among equal-precedence operators. Addition, subtraction, multiplication, and division are normally left-associative: 8−3−1 means (8−3)−1=4. Exponentiation is commonly right-associative: 232 means 23²=512 under that convention. Programming languages may choose different meanings for ^; here it denotes exponentiation, not C++ bitwise XOR.

The conversion algorithm must know these choices. Equal-precedence operators should be popped before an incoming left-associative operator, but not before an incoming right-associative exponentiation. Otherwise 2^3^2 would be grouped incorrectly.

Worked example

14.5 Infix to postfix

Maintain an output sequence and a stack of operators that are waiting for a right-hand expression to finish. Operands go straight to output. Parentheses create a boundary for waiting operators.

Algorithm · pseudocode
ToPostfix(tokens):
    output ← empty sequence
    S ← empty stack
    for t in tokens:
        if t is an operand:
            append t to output
        else if t == '(':
            S.push(t)
        else if t == ')':
            while S not empty and S.peek() != '(':
                append S.pop() to output
            require S not empty
            S.pop()                  // discard '('
        else if t is an operator:
            while S top is an operator and
                  (precedence(S.top) > precedence(t) or
                   (precedence equal and t is left-associative)):
                append S.pop() to output
            S.push(t)
    while S not empty:
        require S.peek() is not a parenthesis
        append S.pop() to output
    return output

This handles precedence and parentheses for a valid tokenized expression; a complete parser must additionally validate the legal operand/operator sequence. Parentheses never appear in the postfix output.

Concept & explanation

14.6 Prefix evaluation and tree connections

To evaluate prefix, scan right to left. Push operands; on a binary operator, the first popped value is the left operand and the second is the right. For − 8 / 6 2, scan 2,6,/ to get 3, then 8, then − to compute 8−3=5. Scan direction reverses the operand-pop convention relative to postfix.

Expressions can be represented as trees: internal nodes are operators and leaves are operands. For (2+3)*4 the root is *, its left child is + with children 2 and 3, and its right child is 4. Prefix visits root before children; postfix visits children before root. This explains why these notations fit recursive structures, rather than treating conversion as a collection of arbitrary stack rules.

Concept & explanation

14.7 Queue applications and reversal

A queue maintains arrival order for tasks waiting to be processed. In breadth-first traversal, enqueue a root, repeatedly dequeue a node, visit it, then enqueue its children in order. Earlier levels are processed before later ones because children join behind all nodes already waiting. Chapter 15 shows a tree example. This is a standard application added to explain queues; the exact classroom application list was not supplied.

A stack reverses order; a queue preserves it. Traversing a list and storing its values in a queue before removing them reproduces forward order. Storing them in a stack produces backward order. Neither by itself changes the original links. Always distinguish manipulating output values from modifying a data structure.

Concept & explanation

15.1 A hierarchy rather than a single chain

Concept · definition

A rooted tree has a distinguished root and parent-child relationships. Every non-root node has exactly one parent, and following parent links reaches the root without cycles. A node may have several children, so a list's single successor becomes a branching hierarchy.

Source example · notation / trace
             A
          /  |  \
         B   C   D
        / \      \
       E   F      G

A is the root. B,C,D are its children and siblings of one another. E's parent is B. E,F,C,G are leaves, meaning they have no children. An internal node has at least one child. Ancestors of F are B and A; descendants of B are E and F. A subtree contains a node and all its descendants.

The depth of a node is the number of edges from the root: depth(A)=0, depth(F)=2. The height of a node is the maximum number of edges from it down to a leaf; height(B)=1 and height(A)=2. A leaf's height is 0. For recursive formulas we may define an empty tree's height as −1, but state that convention: some courses count nodes instead of edges, shifting values by one.

Concept & explanation

15.2 Ordinal and cardinal children

An ordinal, or ordered rooted, tree gives each node an ordered sequence of children: first, second, and so on. A child is recognized by its position among existing children. The order B,C,D matters; swapping B and D gives a different ordered tree.

A cardinal tree uses fixed labeled child slots. A binary tree has left and right positions, each possibly empty. A node with only a left child differs from a node with only a right child. In an ordinal tree with a single existing child, there is just a first child; there is no separate missing-left-versus-missing-right distinction unless the representation adds labeled slots.

Source example · notation / trace
Binary cardinal trees:        same number of nodes, different slots
     A          A
    /            \
   B              B

Do not confuse the number of children with the number of possible child positions. Also, a binary tree is not automatically a binary search tree; search trees impose an additional value-order rule.

Concept & explanation

15.3 First-child, next-sibling representation

For an ordinal tree, a node can store parent, firstChild, and nextSibling. firstChild reaches the first child; following nextSibling walks through that node's remaining siblings in order. This avoids a fixed-size array of child slots when child counts vary.

For the tree above, A.firstChild=B, B.nextSibling=C, C.nextSibling=D, and D.nextSibling=NIL. B.firstChild=E and E.nextSibling=F. E.parent=F.parent=B. D.firstChild=G. A nextSibling link does not mean parent-child: C is B's sibling, not B's child.

Navigation costs depend on stored fields. Parent and first child are Θ(1) with direct pointers. Next sibling is Θ(1). Finding the kth child by walking siblings takes Θ(k), worst Θ(d) for d children. Finding the previous sibling requires scanning from the first child unless a previousSibling pointer is also stored. A pointer representation makes specific links fast; it does not make every relative accessible in constant time.

Concept & explanation

15.4 Insertion and preserving child order

To insert a new leaf as a parent's first child:

Algorithm · pseudocode
InsertFirstChild(parent, x):
    q ← new Node(x)
    q.parent ← parent
    q.firstChild ← NIL
    q.nextSibling ← parent.firstChild
    parent.firstChild ← q
    return q

For existing children [B,C,D], inserting X produces [X,B,C,D]. To insert after a known child c, create q with q.parent=c.parent, q.firstChild=NIL, q.nextSibling=c.nextSibling, then c.nextSibling=q. Both are Θ(1) under constant-time allocation. Inserting as the last child may require Θ(d) sibling traversal without a lastChild pointer. Inserting at a specified child rank includes the cost of locating its predecessor.

The code inserts a fresh leaf. Attaching an existing subtree requires checking that it is detached appropriately and not an ancestor of the new parent; otherwise a cycle or multiple-parent structure could result. Do not assume constant-time validation if the contract does not guarantee those conditions.

Concept & explanation

15.5 Traversal and structural reasoning

An ordinal preorder traversal visits a node before its children, left to right:

Algorithm · pseudocode
Preorder(u):
    if u == NIL:
        return
    visit(u)
    child ← u.firstChild
    while child != NIL:
        Preorder(child)
        child ← child.nextSibling

For the example, preorder is A,B,E,F,C,D,G. Postorder visits all children first, then the parent: E,F,B,C,G,D,A. Every node is visited once and every child/sibling step contributes bounded work, so Θ(n) time. The recursive stack depth follows tree height, O(h+1), reaching Θ(n) for a chain.

Breadth-first traversal uses a queue and visits A,B,C,D,E,F,G. After removing A, enqueue B,C,D; removing B adds E,F behind C,D. This explains the level order. Queue storage can reach Θ(n) for a wide tree. For a rooted tree with n nodes there are n−1 parent-child edges; traversal time can also be understood as O(nodes+edges)=O(n).

Concept & explanation

15.6 Historical extension: binary search trees

Scope label: [S25] only among the supplied content. A BST is a binary cardinal tree in which all keys in a node's left subtree are smaller and all keys in its right subtree are larger, assuming distinct keys. The rule concerns entire subtrees, not only immediate children. We use distinct keys; duplicate policies must be specified separately.

Searching compares x with the current key, then follows left if x is smaller or right if larger. Insertion follows that same path until a missing child slot is found, then places a new leaf there. Each step descends one level, giving O(h+1) time. A well-shaped tree can have logarithmic height, but an ordinary BST is not self-balancing. Inserting increasing keys can make a chain and Θ(n) operation time.

Algorithm · pseudocode
SearchBST(u, x):
    while u != NIL:
        if x == u.key:
            return u
        if x < u.key:
            u ← u.left
        else:
            u ← u.right
    return NIL

InsertBST(u, x):
    if u == NIL:
        return new leaf with key x
    if x < u.key:
        u.left ← InsertBST(u.left, x)
    else if x > u.key:
        u.right ← InsertBST(u.right, x)
    return u

Store root ← InsertBST(root,x) in the caller. This version leaves an already present key unchanged; a distinct-key input never reaches that duplicate case.

Source example · notation / trace
Insert 8, 3, 11, 5:
          8
         / \
        3  11
         \
          5

5 is in 8's left subtree and 3's right subtree, satisfying both ancestor constraints. An inorder traversal—left subtree, node, right subtree—outputs 3,5,8,11. Its sorted result follows from the BST rule.

Concept & explanation

15.7 BST deletion cases

Deleting a leaf removes its parent's link. Deleting a node with one child connects its parent directly to that child, or updates root if necessary. Deleting a node with two children commonly replaces its key with its inorder successor, the minimum key in its right subtree, then deletes that successor from its old location. The successor has no left child, so its removal uses an easier case.

For a tree rooted at 8 with left subtree 3→right 5 and right child 11, deleting 8 can replace its key with 11 and then remove the old leaf 11. Root becomes 11 with left subtree 3→5. A predecessor-based method, using the maximum from the left subtree, is also valid and may give a different shape. State the chosen convention before matching a drawing.

Algorithm · pseudocode
DeleteBST(u, x):
    if u == NIL:
        return NIL
    if x < u.key:
        u.left ← DeleteBST(u.left, x)
    else if x > u.key:
        u.right ← DeleteBST(u.right, x)
    else:
        if u.left == NIL:
            return u.right       // release old u as appropriate
        if u.right == NIL:
            return u.left
        s ← minimum node in u.right
        u.key ← s.key
        u.right ← DeleteBST(u.right, s.key)
    return u

The caller must store returned roots, including root ← DeleteBST(root,x). For records, move the associated record data consistently, not only an unrelated key field. Correct memory release should save any returned child pointer before releasing u. Runtime is O(h+1), with recursive stack O(h+1); worst-case h=n−1. This code explains search-tree problems in the historical paper, not a prediction of current coverage.

Concept & explanation

16.1 Begin with the required behavior

Before choosing an algorithm, state the input, output, promises about the input, and target runtime. Ask whether order is meaningful, duplicates are allowed, data may be modified, and the answer is a value, index, count, or new structure. A perfectly implemented algorithm for the wrong inequality or output type still fails the problem.

Next solve a tiny instance manually and describe a simple correct method. A quadratic brute-force method can reveal what information must be counted even when it is too slow. Then find the bottleneck. Can sorting expose neighbours? Can a sorted half summarize many comparisons? Can a structural promise eliminate half the candidates? Can recursion remove a constant amount of structure per call?

A target bound suggests a family, not a guarantee: O(log n) often suggests discarding a constant fraction; O(n log n) may permit sorting or divide-and-conquer; O(n) suggests scans, bounded work per item, or special integer assumptions. You must still prove the selected method meets the target.

16.2 Current assignment: recursive list interleaving

[A2 Q1; teaching solution, not an official solution.] Given two equal-length singly linked lists, alternate their nodes, starting with the first list, return the new head, and achieve O(n), where n is each input length.

For a=2→4→6 and b=9→11→13, the desired order is 2→9→4→11→6→13. The result begins with a, then b, then the interleaving of the two suffixes. Save those suffix pointers before changing links.

Algorithm · pseudocode
Interleave(a, b):
    require equal-length, disjoint, acyclic input lists
    if a == NIL:                 // b is also NIL by the contract
        return NIL
    aRest ← a.next
    bRest ← b.next
    remainder ← Interleave(aRest, bRest)
    a.next ← b
    b.next ← remainder
    return a

The disjointness assumption prevents a node from being used in both lists and accidentally creating cycles. This version reuses nodes and modifies the original lists. If preserving the input structures were required, allocate fresh output nodes instead and state the additional space.

Trace two-node lists 2→4 and 9→11. The outer call saves aRest=4,bRest=11 and waits. The inner call saves two NIL suffixes; its recursive call returns NIL. It then links 4→11→NIL and returns 4. The outer call receives that head, links 2→9→4, and returns 2. No suffix is lost.

Correctness by length: empty inputs yield an empty interleaving. Assume the suffix call alternates all suffix nodes correctly and returns its head. Placing a then b before that result produces the required alternation of every original node exactly once. The input length decreases, so recursion terminates. Runtime T(n)=T(n−1)+Θ(1)=Θ(n), satisfying O(n). Stack space Θ(n), new node storage Θ(1) beyond the reused nodes.

16.3 Current assignment: count increasing pairs with merge sort

[A2 Q2.] Count pairs of original indices i<j such that A[j]>A[i], with distinct elements, in O(n log n). This is an increasing-pair count, not the usual decreasing inversion count.

Partition pairs into three nonoverlapping groups: both indices in the left half, both in the right half, or one in each. Recursive calls count the first two groups. The challenge is counting cross-half pairs without individually checking every possible pair.

After sorting each half, let L[i] and R[j] be the first unconsumed values. Every original index in the left half precedes every original index in the right half. If L[i]<R[j], then L[i] is also smaller than all remaining R[j..], because R is sorted. Add length(R)−j pairs at once, then output L[i]. If R[j]<L[i], R[j] forms no increasing pair with any remaining left item, so output it without adding. Distinctness removes the tie case; with duplicates use strict comparison and handle equality without counting it.

Algorithm · pseudocode
SortAndCount(A):
    if length(A) ≤ 1:
        return (A, 0)
    split A into original left and right index halves
    (L, leftCount) ← SortAndCount(left half)
    (R, rightCount) ← SortAndCount(right half)
    i ← 0; j ← 0; cross ← 0; B ← empty output
    while i < length(L) and j < length(R):
        if L[i] < R[j]:
            cross ← cross + (length(R)−j)
            append L[i] to B
            i ← i+1
        else:
            append R[j] to B
            j ← j+1
    append unconsumed L and R items to B
    return (B, leftCount + rightCount + cross)

Preallocate B or use constant-amortized append. When R is exhausted, no cross pairs remain with leftover L. When L is exhausted, all relevant cross pairs involving leftover R were counted when their smaller left partners were output.

Trace A=[3,1,4,2]. The left half sorts to [1,3] with count 0; the right sorts to [2,4] with count 0. During the cross merge, 1<2 adds two pairs (with 2 and 4). Then 2<3 causes no count. Then 3<4 adds one. Total 3. Direct enumeration in original indices confirms (0,2),(1,2),(1,3).

The pair classification is exhaustive and disjoint. The merge step counts each cross pair exactly once, at the moment its left value is output. Recursive correctness then gives the total. A merge still advances each pointer only once per item, so T(n)=2T(n/2)+Θ(n)=Θ(n log n). Auxiliary data storage is O(n) with standard merge buffering. The count can reach n(n−1)/2, so use an integer type large enough to hold that value; counters are not restricted to the range of input values.

16.5 Current assignment: minimum absolute difference

[A2 Q4a.] For n≥2 integers, find the smallest |a−b| over two distinct positions in O(n log n). Checking all pairs is correct but Θ(n²). Sorting exposes the important pairs: at least one minimum-difference pair is adjacent in sorted order.

Why? For sorted x₀≤x₁≤…≤x_(n−1), a nonadjacent difference x_j−x_i is a sum of nonnegative adjacent gaps. No larger span can be smaller than every gap inside it. Therefore the minimum over all pairs equals the minimum adjacent gap. Duplicates give gap 0, which is the smallest possible result.

Algorithm · pseudocode
MinimumDifference(A, n):
    if n < 2:
        return NO_PAIR
    B ← comparison-sort A in nondecreasing order
    answer ← B[1]−B[0]
    for i ← 2 to n−1:
        answer ← min(answer, B[i]−B[i−1])
    return answer

For [8,1,13,4], sorted order is [1,4,8,13], with gaps 3,4,5, so answer 3 from values 1 and 4. Sorting costs O(n log n); the scan costs Θ(n), giving O(n log n) total. Use subtraction in a type wide enough for the difference, especially if negative and positive machine integers coexist. If the input must remain unchanged, sort a copy and include its space cost.

Worked example

16.6 The integer-range improvement

[A2 Q4b.] Now every integer is in [0,n999], and the target is O(n). The adjacent-gap idea still works; only the sorting step must change. Counting every possible value would need Θ(n999) counters and fail. Radix sort can exploit digit structure instead.

For n≥2, represent keys in base n. Any value below n999 has at most 999 digits; the included endpoint n999 needs 1000. Use 1000 passes, padding leading zero digits. Stable counting sort by one digit has range 0..n−1 and costs Θ(n+n)=Θ(n). The number 1000 is fixed, independent of n. Thus sorting costs O(1000n)=O(n), followed by the Θ(n) adjacent-gap scan.

The computation model is important: values as large as n999 use up to about 1000 log₂ n bits. Under a word-RAM model with sufficiently large O(log n)-bit words and constant-time digit extraction/arithmetic on these bounded keys, the stated O(n) follows. This is a theoretical assumption; arbitrary-precision arithmetic bit costs or a fixed 64-bit implementation need a separate analysis/representation. Do not claim linear bit complexity without justification. Handle n<2 before choosing base n.

For disjoint lists of lengths p,q, time is O(p+q), more tightly proportional to the number of paired nodes plus constant work to attach a suffix; recursion depth O(min(p,q)+1). Returning a suffix does not require visiting it, so do not claim every suffix node is rewritten.

Show answer

Common mistake

17.1 Incorrect: “There are two loops, so n squared”

Two consecutive length-n loops cost Θ(n)+Θ(n)=Θ(n). Nested loops can be Θ(n²), Θ(n log n), Θ(n), or another class depending on their bounds and resets. Repair the argument by writing each inner count as a function of the outer variable and summing it. For outer i=1,2,4,… with inner i work, sum 1+2+4+…=Θ(n), rather than multiplying log n by its largest inner cost and claiming a tight bound.

Common mistake

17.2 Incorrect: “The largest numeric value is the runtime”

An update j ← 2*j may make j numerically huge in few steps. Runtime counts actions, not the resulting number. In a fixed-word model multiplication is constant-time. In a bit model the bit length matters. Repair: state the model, solve for the iteration count, and only then include per-iteration cost.

Common mistake

17.3 Incorrect: “O is worst, Omega is best”

O and Ω express upper and lower bounds on a chosen function. Best- and worst-case select different runtime functions across inputs of the same size. Repair: say “worst-case time is Θ(n)” or “best-case time is Θ(1),” then support that input case. If you have shown only ≤cn², you have proved O(n²), not necessarily Θ(n²).

Common mistake

17.4 Incorrect: “The loop has log n rounds, so total log n”

If each round scans the current n,n/2,n/4,… items, the sum is Θ(n). If all recursion levels collectively process n data, log n levels give Θ(n log n). Repair: distinguish depth, number of calls, and cost per level. A balanced recursion can have logarithmic stack space and linear or n log n total time.

Common mistake

17.5 Incorrect: “Any f bigger than np is Master case 3”

The basic case needs a polynomial gap and regularity. np log n is bigger than np but smaller than np+ε for every fixed ε>0. Repair: compute p=log_b a, identify an actual ε or use a stated logarithmic extension, and check a f(n/b)≤c f(n) for c<1 in case 3. If the class version is unknown, label that uncertainty rather than inventing a theorem.

Common mistake

17.6 Incorrect: “I can overwrite the link and follow it later”

In reversal, curr.next ← prev destroys curr's old next field. Following curr.next afterward goes backward, not into the unprocessed suffix. Repair: save old next first. Draw a three-node example and inspect which pointer still reaches each node after every assignment. For insert-after, set the new node's next before overwriting the predecessor's next.

Common mistake

17.7 Incorrect: “The head changes automatically in the caller”

A local head parameter can be reassigned without changing the caller's head variable. Repair: return the new head and store it, pass a reference to the head field, or operate on a shared structure with a head member. State which mechanism the pseudocode uses. Recursive reversal and BST deletion both need returned roots stored.

Common mistake

17.8 Incorrect: “Printing backward reverses the list”

Output order and link structure are different. PrintReverse only delays printing until calls return. Repair: check whether the algorithm assigns any next field. If no links change, the original list stays in its original order. A true reversal also changes which node is head and, if stored, tail.

Common mistake

17.9 Incorrect: “Set lo=mid in every binary search”

Updates depend on the invariant and stopping test. Inclusive equality search removes a failed mid with lo=mid+1 or hi=mid−1. A boundary search may retain mid with hi=mid while using lo<hi. Repair: prove each branch retains the answer and strictly shrinks the interval. Check length-1 and length-2 intervals by hand. For mid+1 comparisons, prove mid<hi.

Common mistake

17.10 Incorrect: “The physical array shows queue order”

After wrapping, a circular queue's first logical item may be near the right end. Repair: write f,s,C, list slots (f+k) mod C for k=0..s−1, and show the removed value. Do not use the empty-slot convention with a size-based full test. Do not mod by the current size.

Common mistake

17.11 Incorrect: “All comparison sorts are n log n”

The comparison lower bound says some input requires Ω(n log n) comparisons for any general comparison sort on distinct keys. It does not promise every algorithm achieves that bound. Selection is Θ(n²); quicksort can be Θ(n²) in the worst case. Repair: distinguish problem lower bounds from algorithm upper bounds and specify the input/randomness model for average or expected claims.

Common mistake

17.12 Incorrect: “Integer sorting is always linear”

Counting time is Θ(n+k); radix time is Θ(d(n+b)). Repair: identify k or d,b from the actual key range. For [0,n999], a full frequency array is enormous, but a fixed number of base-n digit passes gives O(n) under the stated arithmetic model. The endpoint requires 1000 digits, not 999. If signed keys or arbitrary precision are involved, state how they are handled.

Common mistake

17.13 Incorrect: “It looks right on the example, so it is correct”

Examples can expose a bug but cannot establish correctness for all valid inputs. Repair: identify a loop invariant, recursive contract, or structural lemma. State initialization, preservation, and the final implication. Include progress/termination. For minimum difference, proving adjacent gaps suffice is the crucial general step; calculating one sorted example is not a substitute.

S5: a sufficient linear recursive solution. Adjacent duplicate pairs are preserved in the input order. At the current start i, if it is the last position, return D[i]. Algorithm · pseudocode
FindSingleLinear(D, i, m):
    if i == m−1:
        return D[i]
    if D[i] != D[i+1]:
        return D[i]
    return FindSingleLinear(D, i+2, m)

Call with i=0,m=2n−1. Removing complete leading pairs preserves the input promise. Eventually either the singleton is first or the last element remains. One constant-work call skips two positions, so worst time Θ(n), hence O(n), and worst stack Θ(n). The source does not require a faster target, so do not assume this fails merely because a faster method exists.

S5: optional logarithmic improvement. Before the singleton, complete pairs start at even zero-based indices. After it, pair alignment shifts. Maintain even lo, even hi, and an odd-length candidate interval. Choose a middle index and round it down to even. If D[mid]==D[mid+1], that is a complete correctly aligned pair before the singleton, so recurse to mid+2..hi. Otherwise the singleton is in lo..mid. FindSingleFast(D, lo, hi):
    if lo == hi:
        return D[lo]

    if mid mod 2 == 1:

17.3. The usual Master theorem requires b>1 so recursive size shrinks by a fixed ratio. n−1 is not n/b for a fixed b>1. Unroll T(n)=T(n−1)+1 instead: n constant increments plus base cost give Θ(n). A theorem's recurrence shape cannot be changed by assigning an invalid b.

B.6 Sorting and searching reference

B.7 Algorithm-design proof templates

Loop invariant: establish the fact before the loop; show every iteration preserves it; combine the fact and stopping condition to prove the result. Recursion: state the contract; prove base cases; assume the smaller call works and justify the combination; show size decreases. Batch counting: partition answers into disjoint groups; prove a sorted-order rule counts every member of one batch; show no overlap. Boundary search: maintain answer-in-interval, justify each discard, and prove strict interval shrinkage.

For a runtime answer, define n, state the cost model, count local work and repetitions/recursive calls, derive the bound, and distinguish any worst/expected/amortized claim. For a pointer answer, state what changes and what head/root pointer is returned.

Appendix C. Glossary

A small dictionary for the language of data structures.

Address: identifier of a memory location. Algorithm: precise procedure for solving a stated problem. Amortized cost: cost per operation derived from a bound on a whole operation sequence, without a probability assumption. Ancestor: node on a path upward toward the root. Array: contiguous indexed storage. Asymptotic bound: eventual growth comparison up to constants.

Auxiliary space: extra working memory beyond the input/output convention being used; include call stacks when reporting it. Base case: recursive input answered without further recursive work. Binary search: search/boundary method that safely halves a candidate interval. Binary tree: tree with labeled left/right child slots. Binary search tree: binary tree with ordered left/right subtree keys. Boolean: true or false value.

Capacity: available storage slots. Cardinal tree: tree with children recognized through fixed labeled slots. Child: direct descendant. Comparison sort: sort whose ordering decisions rely on key comparisons. Contract: preconditions and promised behavior of an operation. Correctness: satisfying the contract for every valid input. Depth: root-to-node edge count under this book's convention. Dequeue: remove a queue's front. Distinct: pairwise different values. Divide and conquer: solve smaller pieces and combine them.

Enqueue: add at a queue's back. Expected time: runtime averaged over specified randomness. FIFO: first in, first out. Frame: information stored for one active function call. Function: named procedure receiving parameters and optionally returning a value. Height: maximum node-to-leaf edge count. Index: position selecting an array element. Infix: operator between operands. Invariant: fact maintained throughout execution. Key: value used to compare or order records.

Leaf: node with no children. LIFO: last in, first out. Linked list: sequence represented by nodes and successor links. Local variable: variable belonging to one function call. Logarithm: exponent needed to obtain a number from a specified base. Majority: value occurring strictly more than half the time. Merge: combine sorted sequences into one sorted sequence. Modulo: remainder operation. NIL: no-node pointer value. Node: object holding data and structural links.

Operand: value used by an operator. Ordinal tree: rooted tree with an ordered sequence of children. Parameter: function's input name. Partition: rearrange items by relation to a pivot. Peek: inspect a stack top without removal. Pointer: stored address of an object or a null value. Pop: remove a stack top. Postfix: operator after operands. Precondition: input requirement of a contract. Prefix: operator before operands; also an initial segment of a sequence, depending on context. Push: add to a stack top.

Queue: FIFO abstract data type. Rank: position in sorted order. Recurrence: equation relating a problem quantity to smaller sizes. Recursion: function calls itself on smaller inputs. Reference: alias or object link; distinguish C++ references from pointer variables. Representation invariant: condition connecting stored fields to a valid abstract object. Root: distinguished top node of a rooted tree. Sequence: ordered collection, possibly with duplicates. Set: unordered distinct membership collection. Sibling: node sharing a parent. Size: number of live items. Stable sort: preserves equal-key record order. Stack: LIFO abstract data type. Subtree: node and its descendants. Tail: final node of a list. Termination: execution eventually reaches a stopping point. Traversal: systematic visit of a structure. Worst case: maximum cost over valid inputs of a fixed size.

Concept & explanation

Bounds, growth, and counting

O(g): eventual upper bound cg. Ω(g): eventual lower bound cg. Θ(g): both, with positive constants independent of n. Best/worst choose input cases; expected needs a randomness model; amortized bounds a sequence's total, without probability.

For fixed k>1, 0<ε<1, c>1: 1 < log log n < log n < logk n < nε < n < n log n < n² < n³ < cn < n! (eventually). Fixed log bases differ only by constants. log(na)=a log n; log(xy)=log x+log y. No log-sum splitting rule. 22n=4n. log log(nn)=log n+log log n.

Σ1=n; Σi=n(n+1)/2; Σi²=n(n+1)(2n+1)/6, indices 1..n. Σ (i=0..k) 2i=2k+1−1. n+n/2+…<2n. Σ (i=1..n) log i=Θ(n log n): upper n log n; lower last n/2 terms.

Concept & explanation

Recurrences / Master theorem

T(n)=aT(n/b)+f(n); constant a≥1,b>1; p=log_b a; constant-size bases. Basic cases:

  1. f=O(np−ε), fixed ε>0 → Θ(np).
  2. f=Θ(np) → Θ(np log n).
  3. f=Ω(np+ε) AND a f(n/b)≤c f(n), c<1 eventually → Θ(f).

Common extension: f=Θ(np logk n), k≥0 → Θ(np logk+1 n). Exact course version unknown; label variant. A log factor is not a polynomial gap. T(n−1), unequal child sizes, or variable a do not fit this theorem.

T(n−1)+1 → Θ(n); T(n−1)+n → Θ(n²); T(n/2)+1 → Θ(log n); T(n/2)+n → Θ(n); 2T(n/2)+n → Θ(n log n). Count all calls, not only depth.

Useful derivations and insertion template

[A1] Σ (i=1..n²) log i=Θ(n² log n). Descending triple loop: Σ (i=1..n) Σ (j=i..n) j=Σ (j=1..n) j²=Θ(n³); j appears for j choices of i. [S25] odd n doubles, then even branch divides by 4: each ≤2-step block halves or quarters n → Θ(log original n).

Algorithm · pseudocode
for i=1..n−1:
  key=A[i]; j=i−1
  while j≥0 and A[j]>key:
    A[j+1]=A[j]; j=j−1
  A[j+1]=key

Sorted prefix invariant; keep key before shifting. Strict > preserves stability. Maximum scan: best=A[0], compare remaining n−1 values; Θ(n) even when already sorted. Majority candidate cancellation needs a second count unless existence is promised.

Concept & explanation

Sorting and selection

Insertion: best Θ(n), random-order average/worst Θ(n²), stable, O(1) extra. Selection: Θ(n²) all input orders, O(n) swaps, generally unstable. Bubble with early stop: best Θ(n), average/worst Θ(n²), stable. Without early stop best Θ(n²).

Merge: Θ(n log n), O(n) buffer, stable if left wins ties. Quick/Lomuto: balanced Θ(n log n), worst Θ(n²), expected Θ(n log n) with random pivot ranks/distinct keys; unstable; stack can be Θ(n). Quickselect: recurse only toward rank k; expected Θ(n), worst Θ(n²). k here is a zero-based global index.

Counting: Θ(n+K) time/space, integer range 0..K−1. Stable placement: prefix counts, scan input backward, decrement count, write output. LSD radix: Θ(d(n+b)), stable digit passes. Comparison sorting lower bound: Ω(n log n) worst-case comparisons, distinct keys.

Concept & explanation

Binary search: sorted array, any match

Algorithm · pseudocode
lo=0; hi=n−1
while lo≤hi:
  m=lo+(hi−lo) div 2
  if A[m]==x: return m
  if A[m]<x: lo=m+1
  else: hi=m−1
return NOT_FOUND

Invariant: if a match remains, it lies in [lo,hi]. Remove failed m; Θ(log n) worst, Θ(1) best, O(1) iterative space. Lower bound / first ≥x uses [lo,hi)=[0,n), while lo<hi: if A[m]<x set lo=m+1 else hi=m. Return lo; test lo<n before access.

Concept & explanation

Valley minimum: strict decrease then increase

Algorithm · pseudocode
lo=0; hi=n−1
while lo<hi:
  m=lo+(hi−lo) div 2
  if A[m]>A[m+1]: lo=m+1
  else: hi=m
return lo

Minimum stays in interval; m<hi makes m+1 valid. Θ(log n), O(1) space. Source example's one-based 4 is zero-based 3.

Concept & explanation

Lomuto partition

Algorithm · pseudocode
pivot=A[hi]; i=lo−1
for j=lo..hi−1:
  if A[j]≤pivot:
    i=i+1; swap(A[i],A[j])
swap(A[i+1],A[hi]); return i+1

Processed regions: ≤pivot then >pivot. Partition is Θ(length), not a complete sort. Quicksort excludes p in both calls. Quickselect keeps only side containing k.

Concept & explanation

Arrays and pointers

Array access Θ(1). Order-preserving insert at i with room: n−i shifts plus write, Θ(n−i+1). Delete at i: Θ(n−i). Shift right from the end for insertion; left from the gap for deletion. Unsorted search Θ(n) worst; sorted search Θ(log n), updates Θ(n) worst.

Ordinary doubling append: Θ(n) resize worst, Θ(1) amortized; copied capacities sum geometrically. Incremental [A1] append/access: active capacity C, prepared 2C, size s∈[C/2,C]. Before append compute copied=2s−C; write new item, increment s, copy those next two indices. At full, promote prepared array and allocate new 4C; double C. Access active array. Initialize separately. Assumes O(1) raw allocation/release; append/access only.

Singly linked: access/search Θ(n) worst. Front update Θ(1); insert/delete after known predecessor Θ(1), but finding it may be Θ(n). Append Θ(1) with tail; pop-back Θ(n) even with tail. Pointer assignment copies address, not node. NIL must be checked before dereference.

Insert after p: q.next=p.next; p.next=q. Delete after p: v=p.next; p.next=v.next; release(v), saving any needed value first. Return/store a changed head.

Concept & explanation

Iterative link reversal

Algorithm · pseudocode
prev=NIL; curr=head
while curr!=NIL:
  saved=curr.next
  curr.next=prev
  prev=curr; curr=saved
return prev

Invariant: reversed processed prefix + untouched suffix. Θ(n) time, Θ(1) extra. Old head becomes tail; cut links correctly.

Concept & explanation

Recursive link reversal

Algorithm · pseudocode
Reverse(p):
  if p==NIL or p.next==NIL: return p
  h=Reverse(p.next)
  p.next.next=p
  p.next=NIL
  return h

Θ(n) time, Θ(n) stack. Print before recursion → forward; print after → reverse output only. Base → smaller input → correct combination → progress. Array recursion should pass boundaries, not copy long suffixes accidentally.

Concept & explanation

Recursive interleaving, equal-length disjoint lists

Algorithm · pseudocode
Interleave(a,b):
  if a==NIL: return NIL
  ar=a.next; br=b.next
  rest=Interleave(ar,br)
  a.next=b; b.next=rest
  return a

One call per pair: Θ(n) time, Θ(n) stack. Save links first. For unequal lengths, return the other suffix when either head is NIL.

Concept & explanation

Stacks, queues, and expressions

Stack=LIFO. Array size s: push writes A[s], increments s; pop checks s>0, decrements, returns A[s]; peek A[s−1]. Linked stack uses head. Fixed-capacity valid ops Θ(1); array growth costs extra.

Queue=FIFO. Circular capacity C, front f, size s. Enqueue checks s<C, writes A[(f+s) mod C], then increments s. Dequeue checks s>0, saves A[f], sets f=(f+1) mod C, decrements s. Empty s=0; full s=C; kth logical item A[(f+k) mod C]. All C slots usable with size field. Resize by copying logical order, then f=0.

Linked queue: head removes, tail adds, Θ(1) with both pointers. Last removal must set head=tail=NIL. Circular physical order differs from FIFO order after wrapping.

Balanced delimiters: push opening; closing must match popped top; reject empty/mismatch; finish empty. Postfix evaluation: pop right, then left; push left op right; finish with exactly one value. Prefix scans right-to-left and pops left first. Tokenize multi-digit operands.

Infix→postfix: operands to output; '(' pushed; ')' pops through matching '('; operator pops higher precedence, plus equal precedence if incoming operator is left-associative. Flush remaining operators; no unmatched parentheses. *,/ precede +,−; exponentiation convention right-associative. Each token pushed/popped O(1) total → Θ(n) time.

Concept & explanation

Assignment design patterns

Increasing pairs i<j,A[i]<A[j]: recurse on original halves; sorted merge: if L[i]<R[j], add len(R)−j and output L[i]; else output R[j]. Add both internal counts. Θ(n log n), O(n) buffer. Decreasing pairs: when L[i]>R[j], add len(L)−i and output R[j]. Strict inequality: do not count ties.

Minimum |a−b|: sort then scan adjacent gaps. Any nonadjacent gap sums nonnegative adjacent gaps. Comparison sort O(n log n). Range [0,n999], n≥2: base n, ≤1000 stable radix passes → O(n), then scan. Needs unit-cost bounded-key arithmetic; full-range counting is not O(n). n<2: no pair.

Concept & explanation

Trees and answer checks

Ordinal: ordered sequence of children. Cardinal: fixed labeled slots (binary left/right). parent/firstChild/nextSibling links each give Θ(1) navigation if stored; kth child may require a scan. First-child insertion: q.parent=p; q.nextSibling=p.firstChild; p.firstChild=q (new leaf). Depth counts root edges; leaf height 0.

BST is historical extension: left subtree keys smaller, right larger. Ops O(h+1), worst Θ(n) without balance. Deletion: leaf / one child / successor or predecessor for two children; store returned root.

Answer: contract + algorithm + correctness + termination + runtime/model. Check empty/singleton, endpoints, duplicates, all-negative, full/empty, wraparound. Θ needs both bounds. State index convention, theorem variant, expected/worst/amortized distinction.
